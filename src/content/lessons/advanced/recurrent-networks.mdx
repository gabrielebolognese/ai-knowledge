A **recurrent neural network** (RNN) reads a sequence one element at a time and keeps a running summary, the <Term slug="hidden-state" />, which it updates at every step and passes to the next.<Cite id="goodfellow2016-rnn" /> Because the same weights are used at every step, one small network can read sequences of any length. The **LSTM** and **GRU** variants add gates that let this memory last much longer, and they power the [Shakespeare generator](/course/project-text/shakespeare-lstm/) and the [BiLSTM sentiment classifier](/course/project-text/sentiment-bilstm/) in the small-text project.

## The vanilla RNN

At step $t$ the network mixes the new input $x_t$ (usually an <Term slug="embedding" />) with the previous hidden state $h_{t-1}$, squashes the result, and uses it both to predict the next token and as memory for the following step.<Cite id="goodfellow2016-rnn" /> Drawn over time, the loop becomes a chain of identical copies, one per token. This is called *unrolling*.

## Why gradients vanish through time

Training an unrolled RNN means running <Term slug="backpropagation" /> backwards along the chain, which is called <Term slug="backpropagation-through-time" /> (BPTT).<Cite id="goodfellow2016-rnn" /> The gradient that reaches an early step has been multiplied by one factor per step in between. In 1994 Bengio, Simard and Frasconi showed that this makes long-range dependencies hard to learn with gradient descent: the product tends either to shrink towards zero or to blow up.<Cite id="bengio1994" />

<MathSteps
  title="The gradient shrinks step after step"
  legend={[
    { symbol: '\\partial h_t / \\partial h_{t-1}', meaning: 'how much the new state changes when the old one changes' },
  ]}
>
  <Step tex="\frac{\partial h_2}{\partial h_1} = w_h\,(1 - h_2^2) = 0.8 \cdot (1 - 0.701^2) \approx \hl{0.41}" words="The chain rule through tanh: its slope 1 − h² times the recurrent weight." />
  <Step tex="0.41^{10} \approx 1.2 \times 10^{-4}, \qquad 0.41^{20} \approx 1.5 \times 10^{-8}" words="Ten steps back the signal is ten thousand times weaker; twenty steps back it is effectively zero." />
  <Step tex="1.1^{50} \approx 117" words="If the factor is above 1 instead, the gradient explodes, which is why RNN training clips gradients." />
</MathSteps>

The <Term slug="vanishing-gradient" /> means a plain RNN learns little from tokens more than roughly 10-20 steps back. The opposite, the <Term slug="exploding-gradient" />, is usually handled with <Term slug="gradient-clipping" />. In practice, long texts are also cut into chunks and gradients stop at chunk borders (truncated BPTT), which the Shakespeare project does.<Cite id="goodfellow2016-rnn" />

## The LSTM: a memory with valves

Hochreiter and Schmidhuber's **Long Short-Term Memory** (1997) adds a second state, the *cell* $c_t$, which is changed only by element-wise multiplications and additions, so information can flow along it for many steps.<Cite id="hochreiter1997" /> Gates, small sigmoid layers with outputs between 0 and 1, decide what to erase, what to write and what to show. The forget gate was added three years later by Gers, Schmidhuber and Cummins, and today "LSTM" means the version with it.<Cite id="gers2000" /> The equations below follow the [PyTorch convention](https://docs.pytorch.org/docs/stable/generated/torch.nn.LSTM.html).<Cite id="pt-lstm" />

<MathSteps
  title="One LSTM step with scalar numbers"
  legend={[
    { symbol: '\\sigma', meaning: 'sigmoid, a valve between 0 and 1' },
    { symbol: 'f, i, o', meaning: 'forget, input and output gates' },
    { symbol: 'g', meaning: 'candidate values to write, between −1 and 1' },
    { symbol: 'c_t', meaning: 'cell state, the long-term memory' },
  ]}
>
  <Step tex="f_t, i_t, o_t = \sigma(W [x_t, h_{t-1}] + b), \quad g_t = \tanh(W_g [x_t, h_{t-1}] + b_g)" words="Each gate looks at the input and the previous output. Suppose this step gives f = 0.9, i = 0.2, o = 0.8 and g = 0.5." />
  <Step tex="c_t = \hl{f_t \cdot c_{t-1}} + i_t \cdot g_t" words="Keep some of the old memory, then add some new. The update is an addition." />
  <Step tex="c_t = 0.9 \cdot 1.0 + 0.2 \cdot 0.5 = 0.9 + 0.1 = \hl{1.0}" words="With an old cell of 1.0: forget 10%, write a little new information." />
  <Step tex="h_t = o_t \cdot \tanh(c_t) = 0.8 \cdot 0.762 \approx \hl{0.609}" words="The output gate decides how much of the squashed memory the rest of the network sees." />
  <Step tex="\frac{\partial c_t}{\partial c_{t-1}} = \hl{f_t}" words="Along the cell, the backward factor is just the forget gate. With f near 1 the gradient survives many steps." example="0.99^50 ≈ 0.61, against 0.41^50 ≈ 0 for the plain RNN" />
</MathSteps>

That last line is the whole trick: the cell is a path where the gradient is multiplied by a learned number close to 1 instead of by a tanh slope times a weight.<Cite id="olah2015" /><Cite id="d2l-lstm" /> PyTorch keeps four weight blocks (one per gate) and two bias vectors per gate, so a layer with input size $I$ and hidden size $H$ has $4H(I+H) + 8H$ parameters: 99,328 for $I = 64, H = 128$.<Cite id="pt-lstm" />

<Analogy breaks="The 'slots' are not separate facts; each number in the cell blends many features.">
An LSTM is a notebook with three valves: an eraser (forget gate), a pen (input gate) and a window (output gate) that decides what others may read right now.
</Analogy>

## The GRU

The **gated recurrent unit**, introduced by Cho and colleagues in 2014, merges the cell and the hidden state and uses two gates: a *reset* gate that decides how much of the old state feeds the candidate, and an *update* gate $z$ that blends old and new.<Cite id="cho2014" /> Its last step, $h_t = (1 - z_t) \odot n_t + z_t \odot h_{t-1}$, is a weighted average: with $z$ near 1 the unit copies its memory forward.<Cite id="d2l-gru" /> A <Term slug="gated-recurrent-unit">GRU</Term> has three weight blocks instead of four, so it is about 25% smaller than an <Term slug="long-short-term-memory">LSTM</Term> of the same size. An empirical comparison by Chung et al. found the two broadly similar on the tasks they tested, so the choice is often made on speed.<Cite id="chung2014" />

## Shapes in PyTorch

`nn.LSTM(input_size, hidden_size, num_layers, batch_first)` returns an output for every step plus the final state:<Cite id="pt-lstm" />

| Tensor | Shape with `batch_first=True` |
|---|---|
| input | `(batch, time, input_size)` |
| output | `(batch, time, hidden_size)` |
| `h_n`, `c_n` | `(num_layers, batch, hidden_size)` |

<Callout type="pitfall">
The default is `batch_first=False`, which expects `(time, batch, features)`. Passing batch-first data to a default LSTM raises no error if the sizes happen to fit; it just reads the batch as time. Also note that `batch_first` does not change the shape of `h_n` and `c_n`.
</Callout>

## Summary

- An RNN applies the same update at every step: $h_t = \tanh(W_{xh} x_t + W_{hh} h_{t-1} + b)$.
- Backpropagation through time multiplies one factor per step, so gradients vanish or explode over long ranges (Bengio et al. 1994).
- The LSTM's cell is updated by addition, and its backward factor is the forget gate, so memory and gradients last longer.
- The GRU uses two gates and no separate cell; it is smaller and often about as good.
- Check `batch_first` and the state shapes whenever you use `nn.LSTM` or `nn.GRU`.
