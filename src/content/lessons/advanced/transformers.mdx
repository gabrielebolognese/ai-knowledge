The **Transformer** is a neural-network architecture that processes a sequence using only attention and small feed-forward networks, with no recurrence.<Cite id="vaswani2017" /> A **GPT** (generative pre-trained transformer) keeps only its decoder half: a stack of identical blocks with a causal mask, trained to predict the next token.<Cite id="radford2019" /> The model in the [code autocompletion project](/course/project-code-autocomplete/code-tiny-gpt/) is a GPT with four such blocks.

## From translation to GPT

Vaswani et al. introduced the Transformer in 2017 for translation, in a paper titled *Attention Is All You Need*. Their base model had 6 layers, vectors of size 512, 8 attention heads and an inner feed-forward size of 2048.<Cite id="vaswani2017" /> Because every position is processed at once instead of one after another, it trained much faster than recurrent models: the larger version reached 28.4 BLEU on English-to-German news translation after 3.5 days on eight GPUs.<Cite id="vaswani2017" />

OpenAI's GPT-2 (2019) used a decoder-only stack and scaled it to 1.5 billion parameters, trained on about 40 GB of web text with a byte-level <Term slug="byte-pair-encoding" /> vocabulary of 50,257 tokens.<Cite id="radford2019" /> Karpathy's [nanoGPT](https://github.com/karpathy/nanoGPT) reproduces this recipe in a few hundred lines and includes a small character-level Shakespeare configuration; the course's project code follows its structure.<Cite id="nanogpt" />

## Inside one block

A GPT block has two sub-layers. First, causal multi-head <Term slug="self-attention" /> lets each token gather information from earlier tokens. Second, an MLP processes each token on its own: a linear layer that widens the vector four times, a <Term slug="gelu" /> non-linearity, and a linear layer back to the original size.<Cite id="nanogpt" /><Cite id="hendrycks2016" /> Each sub-layer is wrapped in two helpers:

- A **residual connection** adds the sub-layer's output to its input, $x \leftarrow x + F(x)$, an idea taken from ResNet. The input passes through unchanged if the sub-layer contributes nothing, and the gradient has a direct path back.<Cite id="he2015-resnet" />
- <Term slug="layer-normalization" /> rescales each token's vector to zero mean and unit variance, with a learned gain and bias.<Cite id="ba2016" /> GPT-2 moved it to the input of each sub-layer ("pre-LN") and added one after the last block, which also trains more stably in small models.<Cite id="radford2019" />

<Analogy breaks="The 'talking' is a weighted average of vectors, not communication in any human sense.">
A block is a meeting followed by private thinking: in attention each token listens to the earlier tokens, and in the MLP it works alone on what it heard. The residual stream is the shared notepad every block reads and adds to.
</Analogy>

## Positions and weight tying

Attention on its own ignores word order: it computes weighted averages over a set. The original Transformer therefore added fixed <Term slug="positional-encoding">sinusoidal positional encodings</Term>, sines and cosines of different frequencies, to the token embeddings.<Cite id="vaswani2017" /> GPT models instead learn one position vector per slot, up to the maximum context length, and add it in the same way.<Cite id="radford2019" /><Cite id="nanogpt" /> A consequence is that a GPT cannot read more tokens than it has position vectors, so generation code crops the context.

<Exercise id="adv-tf-order" />

<Term slug="weight-tying" /> reuses the token-embedding matrix as the output layer. Press and Wolf showed in 2016 that tying the input and output embeddings reduces the parameter count and usually improves language models; nanoGPT and the course model do the same.<Cite id="press2016" /><Cite id="nanogpt" /> For GPT-2's vocabulary at $d = 768$, the shared matrix has $50{,}257 \times 768 \approx 38.6$ million entries, so tying saves that many parameters.

## Counting parameters

Inside a block, the query, key, value and output projections of attention are four $d \times d$ matrices, and the MLP has a $d \times 4d$ and a $4d \times d$ matrix. Biases and LayerNorm add only a few numbers per channel.<Cite id="nanogpt" />

The same rule gives about 0.8 million for nanoGPT's CPU configuration (4 blocks of size 128) and 1.77 million for the project's 4 blocks of size 192.<Cite id="nanogpt" />

## Estimating training compute

Kaplan et al. (2020) estimate that a Transformer needs about $2N$ floating-point operations per token for the forward pass and about $6N$ for forward plus backward, where $N$ is the number of non-embedding parameters. Training on $D$ tokens therefore costs about $C \approx 6ND$.<Cite id="kaplan2020" /> The same paper reported that loss falls smoothly, as a power law, when parameters, data and compute grow together, the <Term slug="scaling-laws" />.<Cite id="kaplan2020" />

  <Step tex="\frac{7.4 \times 10^{12}}{10^{11}\ \text{FLOP/s}} \approx 74\ \text{s}" words="At an assumed 100 GFLOP/s for a laptop CPU, a little over a minute of pure arithmetic; overheads make the real run a few minutes." />

nanoGPT's README reports a validation loss of about 1.88 for that CPU run, against about 1.47 for the 10.65M-parameter model on a GPU.<Cite id="nanogpt" />

## Summary

- A GPT is a stack of blocks: pre-LN causal self-attention and a 4× MLP, each with a residual connection.
- Attention ignores order, so token embeddings are added to position embeddings (learned in GPT, sinusoidal in the original Transformer).
- Weight tying reuses the embedding matrix as the output layer and saves $V \times d$ parameters.
- The blocks hold about $12 L d^2$ parameters: 10.6M for nanoGPT's Shakespeare model, 1.77M for the course's code model.
- Training costs about $6ND$ FLOPs, a quick way to see whether a run fits on a laptop.
