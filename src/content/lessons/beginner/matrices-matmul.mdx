A **matrix** is a rectangular grid of numbers arranged in rows and columns. **Matrix multiplication** combines two matrices by taking the dot product of every row of the first with every column of the second.<Cite id="goodfellow2016-linalg" /> Neural-network libraries use it to compute all the neurons of a layer, for a whole batch of inputs, in a single operation, which is why graphics cards that multiply matrices quickly made deep learning practical.<Cite id="d2l-linalg" />

## What a matrix is

A <Term slug="matrix" /> with $m$ rows and $n$ columns is called an "$m \times n$ matrix" (say "m by n"). In NumPy it is a 2-D array with shape `(m, n)`.<Cite id="d2l-linalg" /> The entry in row $i$ and column $j$ is written $A_{ij}$; mathematicians count from 1, while NumPy counts from 0, so $A_{12}$ is `A[0, 1]` in code.

Matrices appear everywhere in this course:

- a table of data, one example per row and one feature per column;
- a greyscale image, one pixel brightness per cell;
- the <Term slug="weight">weights</Term> of a layer, one row per neuron.

The last use is the one that matters most. Each row of a weight matrix is the weight <Term slug="vector" /> of one <Term slug="artificial-neuron">neuron</Term>.<Cite id="cs231n-nn1" />

## Matrix times vector: several dot products at once

Multiplying a matrix by a vector gives a new vector. Each entry of the result is the <Term slug="dot-product" /> of one row of the matrix with the vector.<Cite id="wiki-matmul" />

<Analogy breaks="Cashiers work independently and can serve different customers; every row of the matrix is applied to the same single vector.">
Picture several cashiers, each with their own price list (one row of the matrix), all ringing up the same basket of goods (the vector). Each cashier produces one total, and the list of totals is the result vector.
</Analogy>

## The shape rule

Before multiplying, check the shapes. A product $AB$ exists only when the number of columns of $A$ equals the number of rows of $B$. The two inner sizes cancel and the two outer sizes give the result.<Cite id="goodfellow2016-linalg" />

## Matrix times matrix

A matrix-matrix product repeats the matrix-vector product for every column of the second matrix. Entry $C_{ij}$ of $C = AB$ is row $i$ of $A$ dotted with column $j$ of $B$.<Cite id="wiki-matmul" />

### Order matters

For ordinary numbers $3 \times 5 = 5 \times 3$, but for matrices the order usually changes the answer. With the matrices above, $BA = \begin{bmatrix}23 & 34\\31 & 46\end{bmatrix}$, which differs from $AB$.<Cite id="goodfellow2016-linalg" /> Often only one order is even defined: a $(2 \times 3)$ matrix can multiply a $(3 \times 4)$ one, but not the other way round. Grant Sanderson's videos explain why: a matrix can be seen as a transformation of space, and doing two transformations in a different order gives a different result.<Cite id="3b1b-linalg" />

## The transpose

The <Term slug="transpose" /> of a matrix, written $A^\top$, flips it over its diagonal: row 1 becomes column 1, row 2 becomes column 2, and a $(2 \times 3)$ matrix becomes $(3 \times 2)$.<Cite id="d2l-linalg" /> In NumPy it is `A.T`. The transpose is the standard fix for a shape mismatch, and it reappears in backpropagation, where gradients flow backwards through $W^\top$.

## Matrix multiplication in NumPy

NumPy computes matrix products with the `@` operator or `np.matmul`.<Cite id="numpy-matmul" />

```python
import numpy as np

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
print(A @ B)     # [[19 22]
                 #  [43 50]]
print(B @ A)     # [[23 34]
                 #  [31 46]]   order matters
print(A * B)     # [[ 5 12]
                 #  [21 32]]   entry by entry: NOT matrix multiplication
```

<Callout type="pitfall">
In NumPy and PyTorch, `*` multiplies matching positions (the element-wise product). Matrix multiplication is `@`. Mixing them up gives results of the right shape but the wrong values, so the bug is easy to miss.
</Callout>

## A layer for a whole batch

Training never feeds one input at a time. Instead, a batch of inputs is stacked as the rows of a matrix $X$, and one product computes every neuron for every input.<Cite id="cs231n-nn1" /> With weights stored one row per neuron, the layer is `X @ W.T + b`: the transpose lines up the shapes, and the bias vector is added to every row by <Term slug="broadcasting" />.

```python
W = np.array([[1, 0, 2],
              [0, 1, -1]])     # 2 neurons x 3 inputs, shape (2, 3)
b = np.array([1, 0])           # one bias per neuron
x = np.array([3, 4, 5])        # one input, shape (3,)
print(W @ x + b)               # [14 -1]  the worked example

X = np.array([[3, 4, 5],
              [1, 1, 1]])      # a batch of 2 inputs, shape (2, 3)
print(X @ W.T + b)             # [[14 -1]
                               #  [ 4  0]]  one row per input
```

The first row of the batch result repeats the worked example; the second row is the same layer applied to the input $[1, 1, 1]$. Shapes: $(2 \times 3) \cdot (3 \times 2) \to (2 \times 2)$, one row per input and one column per neuron.<Cite id="numpy-matmul" />

A real layer works the same way at a larger size. A layer reading 784 pixels with 128 neurons has a $128 \times 784$ weight matrix; for a batch of 64 images, `X @ W.T` multiplies $(64 \times 784)$ by $(784 \times 128)$ and returns $(64 \times 128)$, which is $64 \times 128 = 8192$ dot products in one call.<Cite id="d2l-linalg" />

## Summary

- A matrix is a grid of numbers with shape $(m \times n)$; each row of a weight matrix belongs to one neuron.
- Matrix times vector is one dot product per row; matrix times matrix is one dot product per row-column pair.
- Shape rule: $(m \times n)(n \times p) \to (m \times p)$. Check the inner sizes first.
- Order matters ($AB \neq BA$ in general); the transpose $A^\top$ swaps rows and columns.
- A whole layer for a whole batch is `X @ W.T + b` in NumPy; `*` is element-wise, `@` is matrix multiplication.
