This capstone builds a complete **classifier** from scratch: it generates data, defines a model, measures its error with cross-entropy, works out the gradient by hand and improves the model with gradient descent, all in about 70 lines of [NumPy](https://numpy.org/).<Cite id="numpy-basics" /> The model is <Term slug="softmax-regression" />, the simplest multi-class classifier, and every piece of it was introduced in an earlier lesson of this track.<Cite id="d2l-softmax" />

## The task

The script creates 300 points in a flat plane, 100 for each of three classes. Each class is a cloud of points scattered around its own centre: one at the top, one at the bottom left and one at the bottom right.<Cite id="numpy-generator" /> Each point has two **features** (its $x_1$ and $x_2$ coordinates) and one **label** (0, 1 or 2).

The data is shuffled and split: 240 points for training and 60 held back for testing. The model never sees the test points while it learns, so they show how well it handles new data.<Cite id="goodfellow2016-ml" /> A fixed random seed makes every run print exactly the same numbers.<Cite id="numpy-generator" />

## The four pieces

Every training script in this course, up to the chess engine, has the same four parts.<Cite id="goodfellow2016-ml" />

1. **Model.** Each class gets a score, a weighted sum of the two features plus a bias, exactly like an [artificial neuron](/course/beginner/artificial-neuron/) without an activation. With 2 features and 3 classes, the weights form a $2 \times 3$ matrix $W$, and one [matrix multiplication](/course/beginner/matrices-matmul/) scores every point at once.<Cite id="cs231n-linear" />
2. **Probabilities.** <Term slug="softmax" /> turns the three scores into probabilities that sum to 1. The code subtracts each row's largest score first, which avoids overflow and does not change the answer.<Cite id="cs231n-linear" />
3. **Loss.** <Term slug="cross-entropy" /> averages $-\ln$ of the probability given to the correct class, as in the [loss functions lesson](/course/beginner/loss-functions/).<Cite id="d2l-softmax" />
4. **Update.** <Term slug="gradient-descent" /> moves every weight a small step against its slope, with a <Term slug="learning-rate" /> of 0.1.

<Analogy breaks="A real referee understands the game; the model only nudges nine numbers, with no idea what the points mean.">
Think of three teams sharing a field, and a referee who draws the borders between their areas. After each round the referee looks at every player standing in the wrong area and moves the borders slightly towards fixing those mistakes. After a few hundred rounds the borders barely move any more.
</Analogy>

## The gradient, derived by hand

The heart of the script is one remarkable fact: for softmax followed by cross-entropy, the slope of the loss with respect to each score is just **probability minus target**, $p - y$, where $y$ is the <Term slug="one-hot-encoding">one-hot</Term> label.<Cite id="d2l-softmax" /> The chain rule then passes this back to the weights. ## Reading the results

- **The first loss is 1.0986**, which is $\ln 3$: the untrained model guesses evenly among three classes, exactly as the sanity check in the loss lesson predicts.
- **The loss falls fast, then flattens.** Most of the improvement happens in the first 50 epochs; later epochs only fine-tune the borders.
- **Accuracy** is 96.3% on training points and 95.0% on test points, that is 57 of the 60 unseen points.<Cite id="mlcc-accuracy" /> The two numbers are close, so the model has learned the general pattern rather than memorised its training points.<Cite id="goodfellow2016-ml" />

If matplotlib is installed, the script also saves a picture. It uses matplotlib's non-interactive "Agg" backend, which draws straight to a file and needs no window.<Cite id="mpl-backends" />

## Common mistakes

Most bugs in a from-scratch training loop fall into a few groups, and each one shows up as a recognisable symptom:<Cite id="cs231n-linear" />

- **Shape mix-ups.** Multiplying $X$ (240 × 2) by $W$ in the wrong order, or forgetting the transpose in $X^\top (P - Y)$, raises a NumPy error or silently broadcasts into nonsense. Printing `.shape` after each line is the quickest check.<Cite id="numpy-basics" />
- **Forgetting the average.** Without the division by $n$, the gradient grows with the batch size and a learning rate that worked for 240 points overshoots on 2,400.
- **Adding the gradient.** Writing `W += lr * dW` climbs the loss instead of descending it, so the loss rises every epoch.
- **Measuring on training data only.** A high training accuracy says little on its own; always report the held-out number too.<Cite id="goodfellow2016-ml" />

## What comes next

Softmax regression is a neural network with **no hidden layer**. It cannot draw curved borders, so it would fail on data shaped like rings or the XOR pattern.<Cite id="d2l-softmax" /> The intermediate track adds a <Term slug="hidden-layer" /> with a non-linear activation, which turns this model into a <Term slug="multilayer-perceptron" />, and replaces the hand-derived gradient with backpropagation, which works out gradients automatically for any number of layers. The loop itself stays the same.

## Summary

- A training script has four parts: model, probabilities, loss and update.
- Softmax regression scores each class with a weighted sum, turns scores into probabilities with softmax, and is trained with cross-entropy.
- The gradient with respect to the scores is $p - y$; for a batch it becomes $\frac{1}{n} X^\top (P - Y)$.
- On the 3-cloud data the loss falls from $\ln 3 \approx 1.099$ to 0.110, with 95% test accuracy.
- Its borders are straight lines; a hidden layer is needed for curved ones.
