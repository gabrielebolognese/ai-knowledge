In machine learning, a **dataset** is a collection of examples. Each example has input values called <Term slug="feature">features</Term> and, in <Term slug="supervised-learning" />, a desired output called the <Term slug="label" />.<Cite id="wiki-supervised" /> **Learning** then means adjusting a mathematical function until its outputs come close to the labels, a process called *fitting*.<Cite id="goodfellow2016-ml" /> This lesson shows that idea with three data points and one adjustable number.

## Examples, features and labels

A dataset can be pictured as a table: one row per example, one column per feature and a final column for the label.<Cite id="wiki-feature" />

| Floor area (m²) | Bedrooms | Distance to centre (km) | **Price (€1000)** |
|---|---|---|---|
| 70 | 2 | 5.0 | **210** |
| 120 | 4 | 12.0 | **290** |
| 45 | 1 | 1.5 | **190** |

*Illustrative numbers.* The first three columns are features; the price is the label the model should predict.

Images work the same way. The <Term slug="mnist" /> dataset contains 70,000 greyscale images of handwritten digits, each 28 × 28 pixels.<Cite id="wiki-mnist" /> Each image has 784 features (one brightness value per pixel) and one label, the digit from 0 to 9.

<Analogy breaks="Flashcards are studied by a person who understands them; a model only adjusts numbers to match the answers.">
A dataset is a stack of flashcards. The front of each card shows the features, the back shows the label, and training is practising until the guesses match the backs.
</Analogy>

### Where labels come from

Labels are usually produced by people. MNIST's digits were written by US Census Bureau employees and high-school students, and each image's digit was recorded at collection time.<Cite id="wiki-mnist" /> Labelling is slow and costly, so some projects avoid it. A text model, for example, can use each next character as the label for the characters before it, so the raw text labels itself. The project tracks on small text models and code autocompletion use exactly this trick.<Cite id="wiki-supervised" />

Features do not have to be chosen by hand either. Older systems relied on carefully designed features, such as counts of edges in an image. Deep networks take raw pixels or characters and learn useful features in their hidden layers, which is a large part of why they work so well.<Cite id="wiki-feature" />

## Learning as function fitting

A **model** is a function with adjustable numbers inside it, called <Term slug="parameter">parameters</Term>. Writing the features as $x$ and the label as $y$, the goal is a function $f$ whose prediction $\hat y = f(x)$ ("y-hat") is close to $y$ for every example.<Cite id="goodfellow2016-ml" />

To judge "close", the model needs a score of wrongness, called a <Term slug="loss-function">loss</Term>. A common one is the **mean squared error**: subtract each label from its prediction, square the result, and average.<Cite id="mlcc" />

Here is the whole process with three examples, $(1, 2)$, $(2, 4)$ and $(3, 6)$, and the simplest model there is: $\hat y = w \cdot x$, with one parameter $w$.

**Learning** means finding a good $w$ automatically instead of by trial. Real models do this with <Term slug="gradient-descent" />, which later lessons build step by step, and they have thousands or millions of parameters instead of one.<Cite id="goodfellow2016-ml" />

<Analogy breaks="A radio has one knob you can hear working; a network has millions of knobs that are turned together by an algorithm, not by ear.">
A parameter is like the tuning knob on a radio. The loss is the amount of static, and learning is turning the knob until the static is as low as possible.
</Analogy>

The search can be written in a few lines of plain Python:

```python
xs = [1, 2, 3]          # features
ys = [2, 4, 6]          # labels

def mse(w):
    errors = [w * x - y for x, y in zip(xs, ys)]
    return sum(e ** 2 for e in errors) / len(errors)

for w in [1, 1.5, 2, 2.5]:
    print(f"w = {w}: mean squared error = {mse(w):.3f}")

best = min([w / 10 for w in range(0, 41)], key=mse)
print("best w on a 0.1 grid:", best)
```

It prints losses of `4.667`, `1.167`, `0.000` and `1.167`, then `best w on a 0.1 grid: 2.0`. Trying every value works for one parameter but becomes impossible for millions, which is why the course spends several lessons on [slopes and derivatives](/course/beginner/derivatives/).

## Classification and regression

Supervised tasks come in two main kinds, depending on the type of label.<Cite id="wiki-supervised" />

- <Term slug="regression">Regression</Term>: the label is a number on a scale, such as a price, a temperature or a chess position's evaluation.
- <Term slug="classification">Classification</Term>: the label is one of a fixed set of categories, such as the digits 0-9, the letters A-Z or "spam / not spam".

The distinction matters because it decides the model's output and its loss: regression usually uses mean squared error, while classification uses probabilities and <Term slug="cross-entropy" />, covered in [Loss functions](/course/beginner/loss-functions/).<Cite id="goodfellow2016-ml" />

## Training, validation and test sets

A model that scores well on the examples it learned from has not proved anything yet. What matters is how well it does on new data, an ability called **generalisation**.<Cite id="d2l-generalization" /> To measure it, the data is split into three parts before training starts:<Cite id="wiki-splits" />

- **Training set** (often 70-80%): the examples used to fit the parameters.
- **Validation set** (often 10-15%): used to compare models and choose settings such as the model's size.
- **Test set** (often 10-15%): used once, at the end, to report final performance.

The percentages are common rules of thumb, not fixed rules. MNIST, for example, ships with a fixed split of 60,000 training and 10,000 test images.<Cite id="wiki-mnist" />

```python
import random

examples = list(range(1000))      # stand-ins for 1,000 labelled examples
random.seed(0)
random.shuffle(examples)          # shuffle first, so each part is a fair sample

train = examples[:800]
val = examples[800:900]
test = examples[900:]
print(len(train), len(val), len(test))   # 800 100 100
```

<Analogy breaks="Students can understand the material; a model that memorises gets no credit for 'understanding' on new questions.">
The training set is the homework, the validation set is the mock exam used to decide how to study, and the test set is the real exam, taken once.
</Analogy>

A model that does very well on training data and badly on new data is <Term slug="overfitting">overfitting</Term>: it has memorised the examples instead of learning the pattern.<Cite id="d2l-generalization" />

<Callout type="pitfall">
**Data leakage.** If information from the test set reaches training, for example the same image appears in both sets or the test score is used to pick settings, the reported score will be too optimistic.<Cite id="wiki-leakage" /> Split first, then never look at the test set until the end.
</Callout>

## Summary

- A dataset is a set of examples; each has **features** (inputs) and, in supervised learning, a **label** (the answer).
- A model is a function with **parameters**; learning means adjusting them so predictions match labels, as measured by a **loss** such as mean squared error.
- **Regression** predicts numbers; **classification** picks a category.
- Data is split into **training**, **validation** and **test** sets so that performance on new data can be measured honestly.
