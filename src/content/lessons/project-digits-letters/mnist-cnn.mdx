A **convolutional neural network** (CNN) is a network whose first layers slide small grids of learned weights across the image instead of connecting every pixel to every unit.<Cite id="cs231n-cnn" /> LeCun and colleagues showed in 1998 that this design reads handwritten digits better than any fully connected network of the time; their LeNet-5 reached 0.95% test error on MNIST.<Cite id="lecun1998" /> This lesson builds a small modern CNN in the same spirit, follows a batch through it layer by layer, and trains it to about 99% on a CPU.

## Two ideas that fit images

The MLP from the [baseline lesson](/course/project-digits-letters/mnist-mlp-baseline/) treats the image as 784 unrelated numbers. A convolutional layer adds two assumptions that suit pictures:<Cite id="cs231n-cnn" />

- **Local connectivity.** Each output value looks at a small patch only, for example 3×3 pixels, because strokes, corners and loops are local.
- **Weight sharing.** The same small kernel is used at every position, so a detector for "short vertical stroke" learned in one place works everywhere in the image.

<Analogy breaks="A real stencil is designed by a person; a CNN learns its kernels from data, and many of them look nothing like a neat pattern.">
A convolution is like sweeping a small stencil across a page and writing down, at every position, how well the ink underneath matches the stencil. The sheet of scores is called a *feature map*.
</Analogy>

What PyTorch calls convolution is, strictly speaking, cross-correlation: the kernel is not flipped. Since the kernel is learned, the difference does not matter.<Cite id="pt-conv2d" />

## The architecture

The model has two convolutional blocks followed by a small classifier, the same overall shape as the official PyTorch MNIST example.<Cite id="pt-mnist-example" /> Each block is convolution, ReLU, then **2×2 max pooling**, which keeps the largest value in each 2×2 window and halves the width and height.<Cite id="pt-maxpool" />

<CodeFile path="code/projects/project-digits-letters/models.py" lines="27-56" highlight="40,43,47,50" title="models.py: the CNN" />

`python models.py` sends a dummy batch of 8 images through the network and prints the shape after every layer:

```text
input        (8, 1, 28, 28)
Conv2d       (8, 32, 28, 28)
ReLU         (8, 32, 28, 28)
MaxPool2d    (8, 32, 14, 14)
Conv2d       (8, 64, 14, 14)
ReLU         (8, 64, 14, 14)
MaxPool2d    (8, 64, 7, 7)
Flatten      (8, 3136)
Linear       (8, 128)
ReLU         (8, 128)
Dropout      (8, 128)
Linear       (8, 10)
```

The image gets smaller (28 → 14 → 7) while the number of channels grows (1 → 32 → 64): the network trades position detail for more kinds of features. Early filters respond to edges and stroke fragments, the second block to combinations such as corners and loops.<Cite id="cs231n-cnn" />

**Dropout** with probability 0.5 sits before the last layer. During training it zeroes a random half of the 128 values at every step, which keeps the classifier from relying on a few units; in evaluation mode it does nothing.<Cite id="srivastava2014" />

## The missing channel dimension

The most common error with a first CNN is feeding it a batch of shape `(N, 28, 28)`. `Conv2d` expects `(N, C, H, W)`; given three dimensions, it reads them as one unbatched image `(C, H, W)` with N channels.<Cite id="pt-conv2d" /> `python models.py` reproduces the error on purpose:

```text
RuntimeError: Given groups=1, weight of size [32, 1, 3, 3], expected input[1, 8, 28, 28] to have 1 channels, but got 8 channels instead
```

The fix is to insert the channel dimension with `x.unsqueeze(1)`, which turns `(8, 28, 28)` into `(8, 1, 28, 28)`. This project never meets the error in training, because `ToTensor()` already produces `(1, 28, 28)` per image, but it appears as soon as you build tensors by hand, for example from a NumPy array of drawings.

## Try it

The training script is unchanged; the CNN is its default model. From `code/projects/project-digits-letters/`:

```bash
python train.py --smoke     # 1,000 images, 1 epoch: about 75% in a few seconds
python train.py             # the full run, 3 epochs
```

Measured on the course's test machine (laptop CPU, PyTorch 2.15), the full run took 2 minutes 46 seconds:<Cite id="pt-mnist-example" />

| Epoch | CNN test accuracy | MLP test accuracy | CNN time so far |
|---|---|---|---|
| 1 | 98.43% | 96.19% | 55 s |
| 2 | 98.67% | 97.12% | 105 s |
| 3 | **98.91%** | 97.37% | 158 s |

The CNN makes 109 mistakes on the 10,000 test images, against 263 for the MLP: fewer than half, with four times the parameters but the same training budget. Five epochs (`--epochs 5`, about 4.5 minutes) passed 99% in both runs measured: 99.02% with the default seed and 99.09% with `--seed 1`. Results vary by a few tenths of a percent between machines and seeds.

<Callout type="pitfall">
Each epoch takes about three times longer than for the MLP, because every convolution visits all 784 positions with 32 or 64 kernels. If a CPU run feels slow, `--threads` sets how many cores PyTorch uses, and `--smoke` remains the quick check.
</Callout>

## How it compares with LeNet-5

The model in this lesson is a modern cousin of LeNet-5, not a copy. LeNet-5 took 32×32 inputs, used two convolutional layers with 5×5 kernels and only 6 and 16 feature maps, and shrank its maps with trainable averaging ("subsampling") layers followed by a squashing non-linearity. It had about 60,000 trainable parameters and was trained with a carefully tuned form of gradient descent.<Cite id="lecun1998" />

Three later ideas account for most of the differences here: ReLU activations, max pooling instead of averaging, and dropout in the classifier, together with the Adam optimiser. They make a network of this size easy to train from default settings. The architecture's core idea, convolution and pooling stacked before a small classifier, is unchanged since 1998.<Cite id="cs231n-cnn" />

## Summary

- Convolutional layers reuse small learned kernels at every position (weight sharing) and look at local patches (local connectivity).
- Output width is $\lfloor (W - K + 2P)/S \rfloor + 1$; padding 1 keeps 28×28, each 2×2 pool halves it.
- The CNN has 421,642 parameters, 95% of them in the first fully connected layer.
- A batch must have shape `(N, 1, 28, 28)`; use `unsqueeze(1)` when the channel dimension is missing.
- Three epochs gave 98.91% test accuracy in under three minutes on a CPU, against 97.37% for the MLP.
