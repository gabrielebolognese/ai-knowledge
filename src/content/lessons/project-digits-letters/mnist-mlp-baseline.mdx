A **baseline** is the simplest reasonable model for a task, trained first so that every later model has a number to beat. For MNIST the classic baseline is a small <Term slug="perceptron">multilayer perceptron</Term> (MLP) that looks at the 784 pixel values of an image and outputs 10 scores, one per digit. This lesson builds that model, writes `train.py`, the training script the whole project reuses, and measures about 97% test accuracy in about a minute on a laptop CPU.

## Why start with a baseline

A number on its own says little. If a CNN scores 99%, is that impressive? Only a comparison answers that question. The baseline also tests the plumbing: if a simple MLP cannot learn, the bug is almost certainly in the data or the training loop, not in the architecture.

The official PyTorch MNIST example follows the same idea: one short script that loads the data, defines a model, trains it and reports test accuracy after each <Term slug="epoch" />.<Cite id="pt-mnist-example" />

## The model: 784 → 128 → 10

An MLP cannot take a 28×28 grid directly. `nn.Flatten()` first unrolls each image row by row into a vector of 784 numbers. A hidden layer of 128 units with <Term slug="relu" /> follows, then an output layer with 10 units.

<CodeFile path="code/projects/project-digits-letters/models.py" lines="11-24" title="models.py: the MLP baseline" />

<Analogy breaks="A person reading the ribbon could still notice repeated patterns; the MLP genuinely has no built-in idea of which numbers were neighbours, and must learn every pixel position separately.">
Flattening is like cutting a photo into its 28 rows and taping them end to end into one long ribbon: every pixel is still there, but the fact that pixel 1 and pixel 29 were stacked on top of each other is no longer visible.
</Analogy>

The last layer outputs raw scores called **logits**. The model has no <Term slug="softmax" /> at the end, because PyTorch's <Term slug="cross-entropy">cross-entropy loss</Term> takes logits and applies log-softmax internally, which is faster and numerically safer.<Cite id="pt-ce" />

### One epoch of training

Each step takes a mini-batch of 64 images and performs the same five operations. With 60,000 images, one epoch is 938 steps.

<CodeFile path="code/projects/project-digits-letters/train.py" lines="43-56" highlight="47-51" title="train.py: the training loop" />

1. **Forward pass.** The batch of shape `(64, 1, 28, 28)` goes through the model and comes out as `(64, 10)` logits.
2. **Loss.** Cross-entropy measures how little probability the model gave to the right digits, averaged over the batch.<Cite id="pt-ce" />
3. **Zero the gradients.** PyTorch adds new gradients to old ones unless they are cleared.
4. **Backward pass.** `loss.backward()` computes the gradient of the loss with respect to every weight.
5. **Update.** The optimiser moves every weight a small step against its gradient.

The optimiser is **Adam** with learning rate 0.001. Adam adapts the step size of each weight from running averages of its past gradients, and the default settings from its paper work well on many problems without tuning.<Cite id="kingma2014" />

### Measuring accuracy

After each epoch the script runs the whole test set through the model and counts how often the highest score belongs to the right digit.

`model.eval()` switches layers such as dropout to evaluation behaviour (the CNN uses dropout; the MLP does not, but the habit is cheap), and `@torch.no_grad()` tells PyTorch not to record operations for backpropagation, which saves time and memory.<Cite id="pt-optimization" />

## Try it

From `code/projects/project-digits-letters/`, first run the smoke test. It trains on a fixed sample of 1,000 images for one epoch, checks that the loss went down, and finishes in seconds:

```bash
python train.py --model mlp --smoke
```

```text
MLP on mnist: 101,770 parameters, 1,000 training images, 1 epoch(s)
epoch 1: test accuracy 78.80%  (1 s so far)
smoke test OK: loss 2.01 -> 1.01 in 1 s (chance level is 10%; a full run reaches far higher accuracy)
```

Then the full run on all 60,000 images:

```bash
python train.py --model mlp
```

Measured on the course's test machine (Windows 11 laptop, PyTorch 2.15 CPU build), the whole command took 70 seconds including loading the data:<Cite id="tv-mnist" />

| Epoch | Test accuracy | Time so far |
|---|---|---|
| 1 | 96.19% | 20 s |
| 2 | 97.12% | 43 s |
| 3 | **97.37%** | 62 s |

Your numbers will differ by a few tenths of a percent with a different CPU, PyTorch version or seed (`--seed`). The model is saved as `checkpoints/mnist-mlp.pt`. Write down your final accuracy: it is the baseline.

<Callout type="note">
Larger MLPs do better. Wikipedia's MNIST table lists a 784-800-10 network at 1.6% error, and deeper MLPs trained with distorted copies of the images below 0.5%.<Cite id="wiki-mnist" /> Those results need much more computation and data augmentation; the next lesson gets further with less.
</Callout>

## What the baseline cannot do

The MLP's first layer learns a separate weight for each pixel position. A stroke that appears two pixels further to the right activates completely different weights, so the network has to see enough examples of every pattern in every position. It also spends 100,352 of its 101,770 parameters on that first layer.

A convolutional network fixes both problems by reusing one small set of weights at every position. That is the subject of [A CNN that reads digits at 99%](/course/project-digits-letters/mnist-cnn/).

## Summary

- A baseline is the simplest reasonable model; it gives later models a number to beat and tests the data pipeline.
- The MLP flattens each image to 784 values and has 101,770 parameters, almost all in its first layer.
- `train.py` runs the five-step loop (forward, loss, zero gradients, backward, update) with Adam at learning rate 0.001.
- `--smoke` checks the whole pipeline in seconds; the full run reached 97.37% in about a minute.
- The model outputs logits; `CrossEntropyLoss` applies the softmax itself.
