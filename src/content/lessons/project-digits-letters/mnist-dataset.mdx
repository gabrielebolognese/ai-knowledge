**MNIST** is a collection of 70,000 small grayscale pictures of handwritten digits, each labelled with the digit it shows.<Cite id="wiki-mnist" /> It was assembled by Yann LeCun, Corinna Cortes and Christopher Burges from two NIST handwriting databases and became the standard first benchmark for image classifiers after LeCun's 1998 paper on convolutional networks.<Cite id="lecun1998" /> This lesson downloads it, looks inside it, and writes `data.py`, the data module the rest of the project builds on.

## What is in the dataset

MNIST is split into 60,000 training images and 10,000 test images. Half of each split comes from NIST's Special Database 3, written by Census Bureau employees, and half from Special Database 1, written by high-school students, so the test set contains writers the model never saw during training.<Cite id="wiki-mnist" />

Every image is 28×28 pixels, one byte per pixel. The background is 0 (black) and the ink has high values up to 255 (white); the edges of strokes are grey because the digits were anti-aliased when they were shrunk.<Cite id="lecun1998" />

### How each digit was framed

The original scans were black-and-white images of varying size. LeCun and colleagues scaled each digit so that it fits inside a **20×20 box**, keeping its proportions, and then placed it in the 28×28 image so that its **centre of mass** sits at the centre.<Cite id="lecun1998" /> The centre of mass is the ink-weighted average position: bright pixels pull it towards themselves, faint pixels barely count.

<Analogy breaks="A cardboard cut-out balances on one point in 3D; here the 'weight' of each pixel is simply its brightness, and the balance point is computed, not found by trial.">
Centring by centre of mass is like balancing a cardboard cut-out of the digit on a fingertip and then sliding the whole picture until that balance point is exactly in the middle of the frame.
</Analogy>

This detail looks minor, but it is the reason a model that scores 99% on MNIST can still misread your own drawing. The capstone lesson, [Draw a digit or letter](/course/project-digits-letters/handwriting-app/), repeats these exact steps on canvas drawings.

### The licence question

The original MNIST page does not state a licence. Copies on the web are labelled CC BY-SA 3.0, MIT or public domain by different redistributors.<Cite id="wiki-mnist" /> This course therefore does not redistribute the images: `data.py` downloads them at run time from the mirror that torchvision uses, into a `data/` folder that git ignores.<Cite id="tv-mnist" />

## Downloading MNIST with torchvision

torchvision, PyTorch's computer-vision library, ships a ready-made `Dataset` class for MNIST. Passing `download=True` fetches the four files on first use; afterwards they are read from disk.<Cite id="tv-mnist" /> Each item is an `(image, label)` pair, exactly like the custom datasets in the PyTorch data tutorial.<Cite id="pt-data" />

`load_datasets` in `data.py` wraps this for both datasets of the project. The letters branch is explained in [From digits to letters with EMNIST](/course/project-digits-letters/emnist-letters/).

Every image passes through a **transform** on its way out of the dataset. `ToTensor()` turns the 28×28 grid of bytes into a float tensor of shape `(1, 28, 28)` with values from 0 to 1. The leading 1 is the **channel** dimension: a colour image would have 3. Convolutional layers expect it, so keeping it from the start avoids a classic error later.<Cite id="tv-mnist" />

## Normalising the pixels

Neural networks train more smoothly when their inputs are centred around 0 with a spread of about 1, because the first layer's weights then start in a sensible range. `Normalize(mean, std)` does this for every pixel.<Cite id="tv-normalize" />

The values 0.1307 and 0.3081 are the ones the official PyTorch MNIST example uses.<Cite id="pt-mnist-example" /> They are measured on the training images only; `python data.py --stats` recomputes them and prints the same numbers.

Three things are worth noticing in the grid and in the printout:

1. **The classes are not perfectly balanced.** The digit 5 has 5,421 training images and the digit 1 has 6,742. The imbalance is small, so plain accuracy remains a fair measure here.
2. **Digits fill the middle and leave a margin.** That is the 20×20 box inside the 28×28 frame.
3. **Handwriting varies a lot.** Some 4s are closed, some 7s have a bar, and a few images are hard to read even for a person.

<Callout type="tip">
`num_workers=0` loads batches in the main process. It is slightly slower than parallel workers, but it works on every operating system without extra code; on Windows, parallel workers need the `if __name__ == "__main__":` guard and transforms that can be pickled, which is also why `data.py` uses named functions instead of lambdas.
</Callout>

## Summary

- MNIST has 60,000 training and 10,000 test images of digits, 28×28 grayscale, white ink on black.
- Each digit was scaled to fit 20×20 and centred by centre of mass in the 28×28 frame.
- `ToTensor()` gives a `(1, 28, 28)` float tensor in 0..1; `Normalize(0.1307, 0.3081)` maps it to about -0.42..2.82.
- The normalisation constants come from the training set only.
- The dataset is downloaded at run time and never committed, because its licence is not stated.
