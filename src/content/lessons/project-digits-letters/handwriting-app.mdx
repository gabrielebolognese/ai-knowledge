The **capstone** of this project is a small desktop app: you draw a digit or a letter with the mouse, and the model you trained reads it, showing its three best guesses with probabilities. Building it takes few lines of interface code. The real lesson is the step in between, **preprocessing**: a drawing must be prepared exactly like the training images, or a model with 99% test accuracy fails on the first thing you draw.

## Saving and loading the trained model

`train.py` already saved each model with `save_checkpoint`. A checkpoint is a dictionary holding the model's `state_dict` (the tensors of learned weights), which PyTorch recommends over pickling the whole model object, plus everything needed to use it later.<Cite id="pt-save-load" />

The `dataset` entry is what lets one app serve both models: it tells the preprocessing which framing and which normalisation constants to use. `load_checkpoint` rebuilds the right architecture, loads the weights and calls `model.eval()`, so dropout is off and the same drawing always gets the same answer.<Cite id="pt-save-load" />

## Distribution shift

A test accuracy of 99% is a promise about images **like the test images**. If the inputs change, the promise no longer holds. This is called **distribution shift**: the data seen in use comes from a different distribution than the training data.<Cite id="d2l-shift" /> A canvas drawing differs from an MNIST image in three obvious ways: the colours are reversed, the digit can have any size, and it can sit anywhere on the canvas.

<Analogy breaks="A person adapts to the new framing in a moment; the model has no way to adapt at all, which is why the conversion must happen before it sees the image.">
Showing the model a raw canvas is like handing a cashier who has only ever seen coins a photocopy of a coin, enlarged and in the corner of a page: the information is there, but in a form they never learned to read.
</Analogy>

The fix is to remove those differences before the model sees the drawing, by repeating the steps that created the datasets. For MNIST those steps are known from LeCun and colleagues: scale the digit to fit 20×20 keeping its proportions, then centre it in 28×28 by its centre of mass.<Cite id="lecun1998" /><Cite id="wiki-mnist" />

## The preprocessing pipeline

### Step 1: polarity

MNIST and EMNIST store white ink (high values) on a black background (0).<Cite id="tv-mnist" /> The canvas is the opposite, so mostly light images are inverted.

### Step 2: crop to the ink

`crop_to_ink` cuts away every empty row and column, so it no longer matters where on the canvas you drew. Pixels count as ink above a value of 30, which ignores faint anti-aliasing noise.

<CodeFile path="code/projects/project-digits-letters/preprocess.py" lines="30-35" title="preprocess.py: crop to the ink" />

### Step 3: frame it like the dataset

For digits, `mnist_frame` scales the crop so that its longer side is 20 pixels, pastes it into a black 28×28 image, then shifts it so the centre of mass lands at the centre.

Letters were framed differently: EMNIST centres each character's bounding box in a square frame with a small border and downsamples it with bicubic interpolation, so letters fill more of the image.<Cite id="cohen2017" /> `emnist_frame` reproduces this. Its border was set from a measurement, not by trial on test images: with a border of 3/24 of the letter's size, the longest side of a framed letter comes out at 23.7 pixels, the same average as the EMNIST training letters (digits: 20.0 pixels).

<CodeFile path="code/projects/project-digits-letters/preprocess.py" lines="55-66" title="preprocess.py: EMNIST framing" />

### Step 4: the same tensor transform as training

Finally, `predict` converts the 28×28 image with `drawing_transform`, which uses the same `ToTensor()` and the same mean and standard deviation as training, read from the same `STATS` table in `data.py`. Only the transpose is left out, because a drawing is already upright. Sharing one table means the two pipelines cannot drift apart.

## Measuring what each step is worth

A drawing app is hard to test by hand, so `preprocess.py --check` simulates it. It takes 1,000 test images, redraws each one as a canvas drawing (random size and position, solid black pen on white) and measures accuracy with full preprocessing and with the shortcuts a first version typically takes. Measured on the course machine:<Cite id="d2l-shift" />

| Input given to the model | Digits CNN | Letters CNN |
|---|---|---|
| The stored test image | 99.1% | 93.1% |
| Redrawn, full preprocessing | **99.2%** | **92.2%** |
| Redrawn, canvas shrunk to 28×28 | 14.7% | 4.1% |
| Redrawn, shrunk and inverted (no crop, no centring) | 39.8% | 41.0% |

With full preprocessing, the redrawn images are read as well as the originals. Without it, the same model, with the same weights, falls to near chance. `outputs/preprocess-check.png` shows a few of these inputs side by side.

## Try it

From `code/projects/project-digits-letters/`, after training at least one model:

```bash
python draw_app.py                                     # digits (checkpoints/mnist-cnn.pt)
python draw_app.py --ckpt checkpoints/letters-cnn.pt   # letters
python draw_app.py --selftest                          # no window: draws two shapes in code and predicts
python preprocess.py --check                           # the table above for your own model
```

Draw large, with one continuous gesture per stroke, then release the button. The right mouse button or **Clear** wipes the canvas. If no full model exists yet, the app falls back to the smoke-test checkpoint, which reads digits poorly but proves the pipeline works.

<Callout type="tip">
For letters, remember the classes merge upper and lower case: "a" means A or a. A single vertical bar is genuinely ambiguous between i and l, and the app's top-3 list shows the model hesitating between them.
</Callout>

</Callout>

## Summary

- A checkpoint stores the weights plus the dataset name and class names, so the app knows how to prepare inputs.
- The app draws every stroke twice: on the visible tkinter canvas and into a Pillow image the model reads.
- Distribution shift: a test score only holds for inputs like the test set.
- Preprocessing repeats the dataset's construction: invert, crop to the ink, frame (20×20 plus centre of mass for digits, a bordered square for letters), then the training normalisation.
- Measured: full preprocessing keeps 99.2% on redrawn digits; skipping it gives 15-40%.
