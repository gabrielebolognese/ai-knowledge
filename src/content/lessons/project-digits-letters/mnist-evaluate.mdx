A single accuracy number says how often a model is right, but not *where* it is wrong. A **confusion matrix** fills that gap: it is a table with one row per true class and one column per predicted class, so every cell counts one specific kind of mistake.<Cite id="wiki-confusion" /> This lesson writes `evaluate.py`, which computes per-class accuracy and a confusion matrix for the trained CNN and plots the test images it got wrong with the most confidence.

## Running the whole test set once

`predict_all` runs every test image through the model and keeps four things: the true labels, the predicted labels, the probabilities and the images themselves, so that the mistakes can be shown later.

<CodeFile path="code/projects/project-digits-letters/evaluate.py" lines="21-32" highlight="24,27" title="evaluate.py: predictions for the whole test set" />

Two lines protect the measurement:

- `model.eval()` puts layers such as dropout into evaluation mode. Without it, dropout would keep zeroing half of the classifier's inputs at random, and the same image could receive different answers on different runs.<Cite id="pt-eval-mode" />
- `@torch.no_grad()` turns off gradient tracking, which is only needed for training. Evaluation becomes faster and uses less memory.

The model still outputs logits; `torch.softmax` turns them into probabilities that sum to 1, used below to find mistakes the model was sure about.

## Building the confusion matrix

The matrix starts as a 10×10 grid of zeros. For every test image, the cell at row *true label*, column *predicted label* goes up by one.<Cite id="sklearn-metrics" />

<CodeFile path="code/projects/project-digits-letters/evaluate.py" lines="35-40" title="evaluate.py: counting into a confusion matrix" />

<Analogy breaks="A teacher's tally reflects one pupil's habits; a confusion matrix sums the model's behaviour over thousands of different writers, so its patterns describe the data as much as the model.">
A confusion matrix is like a teacher's tally of a spelling test that records not just how many words were wrong, but which letter was written instead of which.
</Analogy>

Correct answers land on the diagonal. Everything off the diagonal is an error, and its position says which digit was mistaken for which.

## Per-class accuracy, recall and precision

Dividing each diagonal cell by its row total gives the accuracy for each true class, also called its **recall**. Dividing by the column total instead gives the **precision** of each predicted class: when the model says "4", how often is it right?<Cite id="mlcc-metrics" />

<MathSteps
  title="Recall and precision from the matrix"
  legend={[
    { symbol: 'C_{i,j}', meaning: 'count in row i (true), column j (predicted)' },
  ]}
>
  <Step tex="\text{recall}_i = \frac{C_{i,i}}{\hl{\sum_j C_{i,j}}}" words="Of all images that really are digit i (the row), the share recognised as i." example="recall of 9 = 981 / 1009 = 97.2%" />
  <Step tex="\text{precision}_j = \frac{C_{j,j}}{\hl{\sum_i C_{i,j}}}" words="Of all predictions of digit j (the column), the share that were right." example="precision of 4 = 977 / 997 = 98.0%, dragged down by the 14 nines" />
  <Step tex="\text{accuracy} = \frac{\sum_i C_{i,i}}{\sum_{i,j} C_{i,j}} = \frac{9891}{10000}" words="Overall accuracy is the whole diagonal over the whole table: 98.91%." />
</MathSteps>

The script prints the per-class accuracies from worst to best. For this model, 9 is the weakest digit at 97.2% and 1 the strongest at 99.7%. On a balanced test set like MNIST's, overall accuracy is a fair summary; on imbalanced data, per-class recall and precision matter much more.<Cite id="sklearn-metrics" />

Which of the two matters depends on the cost of each mistake. A cheque-reading system that misreads a 9 as a 4 should rather refuse and ask a person, so it cares about precision and can reject predictions whose probability is low. A tool that flags every possible 9 for review cares about recall. The confusion matrix holds the counts for both decisions.<Cite id="mlcc-metrics" />

### Label noise

Some mistakes are the dataset's fault. Northcutt, Athalye and Mueller examined the test sets of ten popular benchmarks and estimated that about 0.15% of MNIST test labels are wrong, roughly 15 images.<Cite id="northcutt2021" /> For a model with 109 errors, that is a noticeable share. Ambiguous images add more: no model can know what a writer meant by a stroke that fits two digits equally well.

<Callout type="note">
This is why differences of a few hundredths of a percent between MNIST models are not meaningful, and why the letters model in the next module cannot approach 99%: its classes are far more ambiguous.
</Callout>

## Summary

- A confusion matrix counts true class (row) against predicted class (column); the diagonal holds correct answers.
- Row-normalised diagonals give per-class accuracy (recall); column-normalised ones give precision.
- Always evaluate with `model.eval()` and `torch.no_grad()`.
- The CNN's most common mistakes are 9→4, 9→7 and 7→2, pairs that look alike.
- Some errors are label noise or genuinely ambiguous images; about 0.15% of MNIST test labels are estimated to be wrong.
