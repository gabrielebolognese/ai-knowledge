A **code corpus** is the body of source code a model learns from. This project needs no download: every Python installation already contains the standard library as several hundred readable `.py` files, written and reviewed by the CPython core developers.<Cite id="python-sysconfig" /> Collected and cleaned, it gives about ten million characters of consistent, idiomatic Python, roughly nine times the 1.1 million characters of the TinyShakespeare file used in nanoGPT's character-level example.<Cite id="nanogpt" />

## Why the standard library

A <Term slug="language-model" /> learns whatever patterns its training text contains, so the text should look like the code you want it to write. The standard library is a good fit for a first code model for three reasons:

- **It is already there.** No account, download or disk space is needed, and every learner gets almost the same corpus.
- **It is consistent.** Most modules follow the PEP 8 style guide: four-space indentation, `snake_case` names and blank lines between functions.<Cite id="pep8" /> A small model learns a consistent style much faster than a mix of styles.
- **It is licensed permissively.** The PSF licence allows use and derivative works, as described below.<Cite id="python-license" />

The trade-off is variety. The standard library is one large, mostly self-contained codebase, so a model trained on it will write "stdlib-flavoured" Python and will know nothing about popular third-party libraries. Larger public datasets such as The Stack exist for that, but they need a Hugging Face login and bring per-file licence obligations.<Cite id="the-stack-smol" />

## Finding the files with sysconfig

The [`sysconfig`](https://docs.python.org/3/library/sysconfig.html) module reports where Python is installed. Its `stdlib` path is the directory holding the platform-independent standard-library files, for example `C:\Users\you\AppData\Local\Programs\Python\Python313\Lib` on Windows.<Cite id="python-sysconfig" /> Inside a virtual environment the call still returns the base installation's library, so the same code works everywhere.

`corpus.py` walks that directory and keeps `.py` files, with three filters:

- It **skips folders** named `test`, `tests`, `idlelib`, `site-packages` and `__pycache__`. The test suite is large and repetitive, IDLE is a GUI application rather than library code, and `site-packages` holds installed third-party packages such as PyTorch, which are not part of the standard library at all.
- It **prunes those folders before descending**, rather than listing every file and filtering afterwards. On a machine with PyTorch installed, `site-packages` contains tens of thousands of files, and walking them first made an early version of the script take over a minute instead of three seconds.
- It **drops files over 200 KB**, which in the standard library are mostly generated tables of data rather than hand-written code.

## Cleaning the text

Raw source needs a little normalisation before a character-level model sees it:

1. **Line endings** become `\n`, so Windows and Unix files look identical.
2. **Tabs** become four spaces. Indentation then has one spelling, which matters for a model whose output must indent correctly.
3. **Rare characters** are replaced by a placeholder, `¤`. The alphabet is fixed at 97 characters: the newline, the 95 printable ASCII characters and the placeholder. Non-ASCII letters appear almost only in comments and docstrings (names of contributors, for example), so the measured corpus contains just 208 placeholders in 9.65 million characters.
4. **File separators**: each file starts with a marker line, `# <|file|> path/to/module.py`. The model learns that a new file begins after it, which typically means a docstring and imports follow, and the completion tool later uses the marker as a stop signal.

A fixed alphabet has a practical benefit: the vocabulary is the same on every machine and for every split, so no character in the validation set can be unknown to the model.

<Analogy breaks="A transcriber can still read the original if unsure; the model only ever sees the cleaned copy, so anything mapped to ¤ is gone for good.">
Cleaning is like a transcriber copying old letters into one typeface: the content stays, but every page now uses the same letters and margins.
</Analogy>

## Splitting by file

To know whether the model has learned Python rather than memorised the corpus, part of the data must stay unseen during training. That held-out part is the **validation set**, used to compare models and settings.<Cite id="wiki-split" /> Here the split is made by whole files: the file list is shuffled with a fixed seed, and the first 10% of files become validation data.

Splitting by lines instead would leak information. Neighbouring lines in one file share imports, class names and local variables, so a validation line whose neighbours were in training is much easier to predict than genuinely new code.<Cite id="wiki-split" /> The fixed seed makes the split reproducible: every run, and every script in the project, sees the same validation files.

Measured on CPython 3.13.3 for Windows, the filters keep **568 files**: 511 for training (8,664,390 characters) and 57 for validation (989,019 characters). Other Python versions and operating systems give somewhat different numbers, so the script prints its own counts.

<Callout type="note">
The research notes for this course counted 1,748 `.py` files in the same standard library. That total includes the test suite and IDLE; about two-thirds of all standard-library source by size sits in those folders.
</Callout>

## The licence, and what is never shipped

CPython is distributed under the PSF License Agreement, together with older notices from BeOpen, CNRI and CWI. It is a permissive, GPL-compatible licence that allows using, modifying and distributing the code and derivative works, provided the copyright notice is kept.<Cite id="python-license" /> A few modules include third-party code under their own permissive terms; the same document lists them, and the full text is in the repository's `LICENSE` file.<Cite id="cpython-license" />

Training a model privately on this code is therefore unproblematic. Even so, the course repository contains only the *scripts*. The corpus is written to `data/`, the trained models to `checkpoints/`, and both folders are excluded from version control. Every learner rebuilds the corpus in a few seconds from their own installation, and a repository with no third-party text or derived binaries is simpler to keep clean.

## Summary

- The standard library is a free, consistent, permissively licensed code corpus of about 10 million characters, already on every machine.
- `sysconfig.get_paths()["stdlib"]` finds it; tests, IDLE and `site-packages` are skipped, and large generated files are dropped.
- Cleaning fixes line endings, tabs and rare characters, giving a 97-character alphabet with file-separator lines.
- The training/validation split is made by file with a fixed seed, so validation measures completion of unseen code.
- Only the scripts are committed; the corpus and checkpoints are rebuilt locally.
