A **GPT** is a stack of <Term slug="transformer" /> decoder blocks trained to predict the next token of a sequence.<Cite id="radford2019" /> This lesson writes one in a single file, `model.py`, following the structure of Andrej Karpathy's nanoGPT and minGPT, which are deliberately small, readable reimplementations of OpenAI's GPT-2.<Cite id="nanogpt" /><Cite id="mingpt" /> The result has 1.8 million parameters, small enough to train on a laptop CPU, yet it contains every part of the architecture that large code models use.

## The architecture at a glance

The model reads a batch of token ids and returns, for every position, a score for every possible next token. Its size is set by five numbers:

| Setting | Symbol | Value | Meaning |
|---|---|---|---|
| `vocab_size` | V | 97 | characters in the alphabet (see the corpus lesson) |
| `block_size` | T | 128 | longest context the model can see |
| `n_layer` | L | 4 | Transformer blocks stacked on top of each other |
| `n_head` | H | 4 | attention heads per block |
| `n_embd` | C | 192 | length of each token's vector ("channels") |

These follow the research notes' recommendation for a CPU-sized code model and sit between nanoGPT's 0.8M CPU example and its 10.65M GPU example.<Cite id="nanogpt" /> Karpathy's video *Let's build GPT* develops the same design step by step for a Shakespeare model, and is the best companion to this lesson.<Cite id="lets-build-gpt" />

## Step 1: embeddings

A batch arrives as integers with shape `(B, T)`: B windows of T characters. Two lookup tables turn them into vectors. The token embedding `wte` gives each of the 97 characters a learned vector of length 192. The position embedding `wpe` gives each of the 128 positions its own learned vector, because attention by itself ignores order.<Cite id="vaswani2017" /> The two are added, giving `x` with shape `(B, T, C)`.

The original Transformer used fixed sine and cosine patterns for positions; GPT-2 and nanoGPT learn them instead, and so does this model.<Cite id="radford2019" />

## Step 2: causal self-attention, shape by shape

<Term slug="self-attention" /> lets each position gather information from other positions. Every position produces a *query* (what it is looking for), a *key* (what it offers) and a *value* (what it passes on). The weight between two positions is the softmax of their query–key <Term slug="dot-product" />, scaled by the square root of the head size.<Cite id="vaswani2017" />

The **causal mask** is what makes this a model that can generate code. When predicting the character at position $t$, the model must not see positions after $t$, because at generation time they do not exist yet.<Cite id="vaswani2017" /> The mask sets those scores to $-\infty$ before the softmax:

  <Step tex="S + M = \begin{bmatrix} 1 & \hl{-\infty} & \hl{-\infty} \\ 2 & 1 & \hl{-\infty} \\ 0 & 1 & 1 \end{bmatrix}" words="Everything above the diagonal is replaced by minus infinity. Each row now only contains the token itself and earlier tokens." />
  <Step tex="\operatorname{softmax}(S + M) = \begin{bmatrix} 1 & 0 & 0 \\ \hl{0.731} & \hl{0.269} & 0 \\ 0.155 & 0.422 & 0.422 \end{bmatrix}" words="Because e to the minus infinity is 0, masked positions get exactly zero weight, and each row still sums to 1." example="row 2: e²/(e² + e¹) = 7.389 / 10.107 = 0.731" />
</MathSteps>

In `model.py` the explicit version builds a lower-triangular boolean matrix with `torch.tril` once and uses `masked_fill` to apply it. The default path calls PyTorch's fused `scaled_dot_product_attention` with `is_causal=True`, which computes the same result faster.<Cite id="pt-sdpa" /> The file's self-test checks that the two paths agree.

## Step 3: the MLP and the block

After attention, each position passes through a small two-layer network on its own: a linear layer that expands 192 channels to 768, a GELU nonlinearity, and a linear layer back to 192. Attention moves information *between* positions; the MLP processes it *within* each position.

A **block** wraps both parts the way GPT-2 does: <Term slug="weight">weights</Term> pass through LayerNorm first ("pre-LN"), and each sub-layer's output is *added* to its input rather than replacing it.<Cite id="radford2019" /> The additions are residual connections, introduced for very deep image networks, which give gradients a direct path through the stack.<Cite id="he2016" /> LayerNorm rescales each token's vector to zero mean and unit variance, which keeps training stable.<Cite id="ba2016" />

## Step 4: the output head and weight tying

After the last block and a final LayerNorm, a linear layer `lm_head` maps each 192-number vector to 97 scores, the **logits**, one per possible next character. The training loss is cross-entropy between those logits and the true next character, computed at all T positions at once, so one window of 128 characters provides 128 training examples.<Cite id="lets-build-gpt" />

The output layer reuses the token-embedding matrix (`lm_head.weight = wte.weight`). Press and Wolf showed that tying the input and output embeddings reduces the parameter count and usually improves language models; GPT-2 and nanoGPT do the same.<Cite id="press2016" /><Cite id="nanogpt" />

## Counting the parameters

Counting parameters by hand is a good check that you understand the shapes. Per block, attention has four $C \times C$ matrices (query, key, value, output) and the MLP has two $C \times 4C$ matrices.

  <Step tex="L \cdot 444{,}864 = \hl{1{,}779{,}456}" words="Four blocks." />
  <Step tex="1{,}779{,}456 + \underbrace{97 \cdot 192}_{\text{wte}} + \underbrace{128 \cdot 192}_{\text{wpe}} + \underbrace{2 \cdot 192}_{\text{ln\_f}} = \hl{1{,}823{,}040}" words="Plus the token table (18,624), the position table (24,576) and the final LayerNorm. </MathSteps>

Almost all the parameters sit in the blocks; the embeddings are tiny because the vocabulary is only 97 characters. That changes with a larger vocabulary, as the BPE lesson shows. For scale, the largest GPT-2 model has 48 layers, 1,600 channels and 1.5 billion parameters, roughly 850 times more.<Cite id="radford2019" />

## Checking the shapes

Run `python model.py`. It builds a toy model with V = 10, T = 8 and C = 8, and prints:

- `logits shape: (2, 8, 10) (B, T, V)`: one score per vocabulary entry, for every position of both windows.
- An untrained loss close to $\ln V = \ln 10 \approx 2.30$. A freshly initialised model guesses roughly uniformly, so its cross-entropy is about $\ln V$; a starting loss far from that usually means a bug in the loss or the targets.<Cite id="lets-build-gpt" /> For the real model the value to expect is $\ln 97 \approx 4.57$.
- `explicit mask == scaled_dot_product_attention: True`.
- `default config: 1,823,040 parameters`, matching the hand count above.

<Callout type="tip">
PyTorch also has a built-in `nn.TransformerEncoderLayer` that can act as a GPT block when given a causal mask. Writing the block by hand, as here, costs about 40 lines and makes every shape visible, which is why nanoGPT and this course do it that way.
</Callout>

## Summary

- A GPT is token and position embeddings, a stack of pre-LN Transformer blocks, a final LayerNorm and an output head tied to the token embedding.
- Attention reshapes `(B, T, C)` into H heads, builds a `(B, H, T, T)` score table, masks the future with minus infinity, and returns to `(B, T, C)`.
- The MLP expands to 4C and back; residual connections and LayerNorm keep the stack trainable.
- The default model has 1,823,040 parameters, about $12C^2$ per block, and should start training at a loss near $\ln 97 \approx 4.57$.
