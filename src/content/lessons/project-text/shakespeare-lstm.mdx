A **character-level recurrent network** reads text one character at a time and carries a vector of numbers, its *hidden state*, from each step to the next. The hidden state works as a memory, so the network is not limited to the last three characters like the MLP of the previous lesson. In 2015 Karpathy showed that such networks, trained on raw text, learn to write plausible-looking Shakespeare, Wikipedia markup and C code.<Cite id="karpathy2015-rnn" /> This lesson trains a GRU on the names, then a two-layer LSTM on 1.1 million characters of Shakespeare, on a laptop CPU.

## From a fixed window to a memory

The MLP saw exactly three characters. A <Term slug="recurrent-neural-network" /> instead applies the same small network at every position: it takes the current character and the previous hidden state, and produces a new hidden state and scores for the next character. Because the weights are shared across time, it handles text of any length.

<Analogy breaks="A reader remembers meaning; the hidden state is a few hundred numbers that the network has learned to use, and nobody chose what each one stores.">
The hidden state is like the running impression a reader keeps while reading aloud: it is updated after every character and coloured by everything read so far.
</Analogy>

Plain recurrent networks are hard to train over long spans. Backpropagating through many steps multiplies many factors together, so gradients shrink towards zero or blow up; Bengio, Simard and Frasconi analysed this problem in 1994.<Cite id="bengio1994" /> Gated cells were designed to reduce it.

### The LSTM cell

The <Term slug="long-short-term-memory">LSTM</Term> of Hochreiter and Schmidhuber adds a second vector, the *cell state*, which is changed only by element-wise multiplication and addition.<Cite id="hochreiter1997" /> Three gates, each a sigmoid with values between 0 and 1, decide how much of the old memory to keep, how much new information to write and how much to reveal.<Cite id="olah2015" />

The <Term slug="gated-recurrent-unit">GRU</Term> of Cho et al. is a lighter variant with two gates and no separate cell state; its new state is a gated blend of the old state and a candidate.<Cite id="cho2014" /> `char_rnn.py` supports both with `--cell gru` or `--cell lstm`, using PyTorch's built-in layers.<Cite id="pt-lstm" />

## The model

<CodeFile path="code/projects/project-text/char_rnn.py" lines="32-45" highlight="36,37,38,40,44,45" title="char_rnn.py: embedding, GRU or LSTM, and a linear head" />

The network has three parts: an embedding for each character, the recurrent layers and a linear layer that turns each hidden state into scores for the next character. `batch_first=True` makes the input shape (batch, time, features); PyTorch's default puts time first, a common source of silent bugs.<Cite id="pt-lstm" /> The forward pass returns the new state as well, so the caller can hand it to the next chunk.

## Training on a long stream

TinyShakespeare is a single file of 1,115,394 characters drawn from Shakespeare's plays, with 65 distinct symbols: letters, punctuation, spaces and line breaks.<Cite id="tinyshakespeare" /> Shakespeare's text is in the public domain and the char-rnn repository is MIT-licensed; the script downloads the file rather than bundling it, only to keep the repository small.<Cite id="char-rnn" /> The first 90% (1,003,854 characters) is used for training and the last 10% for validation, as in nanoGPT.<Cite id="nanogpt" />

The text is cut into 32 rows of equal length that are read side by side, and each training step takes the next 100 characters of every row. The hidden state is carried from one chunk to the next, so the network can use context from earlier chunks, but gradients stop at the chunk border. This is *truncated backpropagation through time*.

<CodeFile path="code/projects/project-text/char_rnn.py" lines="142-155" highlight="143,144,149,150,153,154" title="char_rnn.py: carry the memory, cut the gradient, clip" />

Lines 143-144 restart from the top of the text, with an empty memory, when a row runs out. Line 149 (`state = detach(state)`) detaches the state: its values flow forward, but its computation history is dropped, so line 150 hands the memory to the model while line 153 (`loss.backward()`) only backpropagates through the current 100 characters. Line 154 (`clip_grad_norm_`) clips the gradient: if the combined size (norm) of all gradients exceeds 1.0, they are scaled down to 1.0, which prevents rare exploding steps from wrecking the weights.<Cite id="pt-clip-grad" /> Karpathy's char-rnn uses clipping for the same reason.<Cite id="char-rnn" />

## Results on names: the third generator

First, the GRU on the names, with the same train/dev split as the bigram table and the MLP. The names are joined into one stream separated by `.`, so the GRU makes exactly one prediction per character plus one for the end of each name, like the earlier models. `python char_rnn.py --data names` (1 layer, 128 units, 66,555 parameters) took about 1.5 minutes on the test machine:

| Step | Train loss | Dev loss |
|---|---|---|
| 500 | 2.180 | 2.067 |
| 1,000 | 2.004 | 2.026 |
| 1,500 | 1.938 | **2.022** |
| 2,000 | 1.892 | 2.034 |
| 3,000 | 1.833 | 2.071 |

After step 1,500 the training loss keeps falling while the dev loss rises: the network is starting to memorise the 25,626 training names. The script therefore keeps the weights with the best dev loss (early stopping). The progression across the module is now complete:

| Model | Context | Parameters | Dev loss | Perplexity |
|---|---|---|---|---|
| Uniform guess | none | 0 | 3.30 | 27.0 |
| Bigram counts | 1 character | 729 probabilities | 2.45 | 11.6 |
| Bengio-style MLP | 3 characters | 11,897 | 2.14 | 8.5 |
| GRU | the whole name so far | 66,555 | **2.02** | **7.6** |

## Results on Shakespeare

`python char_rnn.py --data shakespeare` trains a 2-layer LSTM with 256 units per layer (876,929 parameters) for 2,000 steps: about 10 minutes on the test machine, and 19 minutes in a rerun while other training jobs shared the CPU. The rerun reproduced the validation loss (1.4979) and the sample below exactly, because the seed is fixed. To see what happens after that point, the test machine also ran 3,000 steps (13 minutes, with other jobs sharing the CPU):

| Step | Train loss | Validation loss | Time |
|---|---|---|---|
| 0 | | 4.1760 | |
| 500 | 1.941 | 1.694 | 1.8 min |
| 1,000 | 1.472 | 1.579 | 5.0 min |
| 1,500 | 1.367 | 1.518 | 7.3 min |
| 2,000 | 1.317 | **1.498** | 9.7 min |
| 2,500 | 1.278 | 1.503 | 11.7 min |
| 3,000 | 1.250 | 1.507 | 13.2 min |

The validation loss stops improving after about 2,000 steps (each step reads 32 × 100 characters, so 2,000 steps are about six passes over the training text) while the training loss keeps falling, so 2,000 is the default and the script keeps the best weights in any case. In the first rows the training loss is above the validation loss: it is averaged over the steps since the last report, while the model was still improving, and it is measured with dropout switched on.

For comparison, nanoGPT's README reports a validation loss of about 1.88 for a small character-level transformer trained on a CPU for a few minutes on the same file, and about 1.47 for a 10.65-million-parameter transformer trained on a GPU.<Cite id="nanogpt" /> The LSTM here, with a similar number of parameters (0.88 million against about 0.8 million), does better than that small transformer, but it also saw about four times as many characters during training (2,000 steps × 3,200 against 2,000 × 768), so this is not a verdict on the architectures. The losses are comparable because both use the same 65-character vocabulary and the same 90/10 split.

### What the samples look like

At temperature 0.8, prompted with `ROMEO:`, the test machine produced:

```text
ROMEO:Npressive
The parents rolours when thou dost part of mine.
Give me to be my good most severer presence
Of your reasons and Bushy friends of England,
And whom for that friends to the seasons appeal.

QUEEN ELIZABETH:
No noble lord,
Being thee, nor slain? how doth my life,
Which. Shall I use of the gods put of wears,
I am this secret with put her honours.

Second Servingman:
A left more shall be the
```

The model has clearly learned the format: speaker names in capitals followed by a colon, line breaks, archaic words and mostly correct spelling. It has not learned meaning. Sentences start plausibly and wander, and characters speak to nobody in particular. Karpathy's samples from much larger LSTMs show the same pattern at a higher level of polish.<Cite id="karpathy2015-rnn" />

With `--temperature 0` (greedy decoding, always the most likely character) the same model gets stuck at once:

```text
ROMEO:
The sea the seat of the state,
And the sea the seat of the state,
And the sea the seat of the state,
```

Each character is the single most likely one, and the most likely continuation of this line leads back into the same line. Sampling at a temperature around 0.8, optionally with top-k, avoids such loops while keeping most characters on the likely side.

## Try it

From `code/projects/project-text/`:

```bash
python char_rnn.py --smoke                    # GRU on names, 60 steps: seconds
python char_rnn.py --data names               # about 1.5 minutes, best dev loss about 2.02
python char_rnn.py --data shakespeare         # downloads 1.1 MB; about 10 minutes on a laptop CPU
python generate.py --model checkpoints/rnn-shakespeare.pt --prompt "JULIET:" --temperature 0.8
python generate.py --model checkpoints/rnn-shakespeare.pt --temperature 0     # greedy: watch it loop
python char_rnn.py --data shakespeare --cell gru --steps 1000 --hidden 128    # a smaller, faster GRU
```

The `--prompt` text is fed through the network first, so the generated text continues from it. Change one thing at a time (cell type, hidden size, sequence length) and compare validation losses at the same number of steps.

## Summary

- A recurrent network carries a hidden state from character to character, so its context is not limited to a fixed window.
- The LSTM's cell state is updated by multiplying and adding, and its forget gate lets gradients survive many steps; the GRU is a lighter two-gate variant.
- Long texts are trained in chunks with the state carried forward but detached (truncated backpropagation through time) and with gradient clipping.
- On names, the GRU reaches a dev loss of 2.02 (bigram 2.45, MLP 2.14) and starts to overfit after about 1,500 steps.
- On TinyShakespeare, a 2-layer LSTM reaches 1.50 nats per character in about 10 minutes on a CPU and writes text with the right form but no meaning.
