A **bigram model** predicts the next character from the one character before it, using nothing but counts; it is the simplest <Term slug="n-gram">n-gram model</Term>. Built from 32,033 first names, it is the simplest possible <Term slug="language-model" />: a table that says, for example, how likely "a" is to follow "m".<Cite id="makemore" /> This lesson builds the table, samples new names from it, and measures how good it is with the same loss that every later model in this track uses.

## The data: 32,033 names

The file `names.txt` holds one lowercase name per line, from "emma" and "olivia" down to rare names.<Cite id="names-txt" /> It comes from Andrej Karpathy's makemore project, which built it from the US Social Security Administration's baby-name records.<Cite id="makemore" /><Cite id="ssa-names" /> The course bundles a copy: the repository is MIT-licensed and the underlying SSA data is a US government work, so redistribution is allowed (details in `bundled/LICENSES.md`).

`text_data.py` loads the names, shuffles them once with a fixed seed and splits them 80/10/10 into 25,626 training, 3,203 development (dev) and 3,204 test names, the same split makemore uses.<Cite id="makemore" /> Every model in this track uses this exact split, so their losses can be compared directly.

### A vocabulary of 27 symbols

The names use the 26 letters a-z. One more symbol, `.`, marks both the start and the end of a name. So "emma" becomes `.emma.`, which contains five pairs of neighbours, called *bigrams*: `.e`, `em`, `mm`, `ma` and `a.`. The first pair teaches the model how names begin; the last teaches it when to stop.

## Counting

`count_bigrams` walks through every training name and adds 1 to cell `N[a, b]` each time character `b` follows character `a`.

<CodeFile path="code/projects/project-text/bigram.py" lines="18-32" highlight="23,24,25,31,32" title="bigram.py: count the pairs, then normalise each row" />

The result is a 27×27 table holding 182,625 counts. The most common pairs are `n.` (5,404 names end in n), `a.` (5,273) and `an` (4,389). To turn a row into probabilities, divide each count by the row total: of the 25,626 training names, 3,545 start with "a", so the probability that a name starts with "a" is about 0.138.

<Analogy breaks="A real reader also uses earlier letters and knows what names sound like; the table looks only one letter back.">
The table works like a reader who has seen thousands of names and remembers only one thing: after this letter, which letters came next, and how often.
</Analogy>

### Smoothing: never say never

Some pairs never appear in the training names. With raw counts, their probability is exactly 0. That is a problem: 5 dev names contain such a pair (for example "jp" in the name "jp", or "kv" in "kvon"), and a probability of 0 means an infinite loss. Running `python bigram.py --smoothing 0` shows exactly this: the dev loss becomes `inf`.

The fix is *add-one smoothing*: add 1 to every cell before normalising, so every pair keeps a small chance.<Cite id="jm-ch3" /> Line 31 does this. With 109 empty cells out of 729, the extra counts change the common probabilities very little.

## Sampling a name

To write a new name, start at `.`, look up that row, draw the next character with those probabilities, then repeat from the new character until `.` comes up again. `sample_name` in `bigram.py` does this, and the drawing itself happens in `sampling.py`, which every generator in this track shares.

<CodeFile path="code/projects/project-text/sampling.py" lines="11-30" highlight="18,20,21,22,30" title="sampling.py: temperature and top-k" />

Two knobs change how adventurous the sampling is.<Cite id="hf-generate" />

- **<Term slug="sampling-temperature">Temperature</Term>** $T$ divides the scores before the <Term slug="softmax" />. Below 1 it favours the likely letters even more; above 1 it flattens the choice.
- **Top-k** keeps only the $k$ highest-scoring letters and renormalises, so a rare letter can never be drawn by bad luck.<Cite id="fan2018" />

For the bigram model, the score of a letter is simply the logarithm of its probability, so $T = 1$ without top-k reproduces the table exactly.

## How good is the model? The loss

A language model is judged by how much probability it gives to the text that really comes next. For each pair in the dev names, take the probability the table gives to the true next character, take $-\ln$ of it, and average. This is the average *negative log-likelihood*, the same quantity as the <Term slug="cross-entropy" /> loss used to train networks.<Cite id="jm-ch3" />

</MathSteps>

<Exercise id="bigram-uniform-loss" />

The <Term slug="perplexity" /> reading makes the numbers concrete: the bigram model has narrowed each choice from 27 equally likely symbols to the uncertainty of about 11.6. Train and dev loss are almost identical (2.4548 and 2.4533), which is expected: a table of 729 probabilities estimated from 182,625 pairs has nothing to overfit.

## Summary

- A bigram model is a 27×27 table of next-character probabilities, built by counting pairs in 25,626 training names.
- Add-one smoothing prevents zero probabilities; without it the dev loss is infinite.
- Sampling repeats "look up the row, draw a letter"; temperature and top-k control how adventurous the draw is.
- The loss is the average $-\ln p$ of the true next character: 3.30 for guessing, 2.45 for the bigram table (perplexity about 11.6).
- One letter of context is not enough for coherent names, which motivates the neural model in the next lesson.
