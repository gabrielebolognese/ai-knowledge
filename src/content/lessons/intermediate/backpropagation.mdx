**Backpropagation** is the algorithm that computes how much the loss changes when each weight of a neural network changes slightly, that is, the <Term slug="gradient" /> of the loss with respect to every parameter.<Cite id="goodfellow2016-mlp" /> It applies the chain rule of calculus systematically, starting at the loss and working backwards through the network.<Cite id="d2l-backprop" /> Those gradients are exactly what <Term slug="gradient-descent" /> needs, so backpropagation is the engine behind training every network in this course.

## The idea in one picture

Any calculation can be drawn as a <Term slug="computational-graph" />: each node is one simple operation (add, multiply, ReLU) and each arrow carries a number to the next node.<Cite id="cs231n-backprop" /> The forward pass computes the values from left to right. The backward pass then sends gradients from right to left, and each node needs to know only one thing: its own *local derivative*, how its output changes when its input changes.<Cite id="cs231n-backprop" />

The rule at every node is the chain rule: the gradient arriving from above (the **upstream gradient**) times the local derivative gives the gradient to pass further back.<Cite id="cs231n-backprop" /> Three node types cover most of what follows:

- an **add** node passes the upstream gradient to both inputs unchanged
- a **multiply** node gives each input the upstream gradient times the *other* input
- a **ReLU** node passes the gradient if its input was positive and blocks it otherwise.

<Analogy breaks="Blame in a real group project is negotiated; here it is exact arithmetic, and it only says what a tiny change would do, not a big one.">
Backpropagation is like assigning blame after a group project. The final grade is known; going backwards, each member passes blame to the people whose input they used, in proportion to how much that input affected their part.
</Analogy>

With a <Term slug="learning-rate" /> of $\eta = 0.05$, one gradient-descent step gives $v_1 = 2 - 0.05 \cdot 1.5 = 1.925$, $c = -0.05$, $w_{11} = 0.4$, $w_{12} = 0.3$ and $b_1 = -0.1$. A new forward pass gives $z_1 = 0.9$ and $\hat y = 1.925 \cdot 0.9 - 0.05 = 1.6825$, so the loss falls from 0.5 to about 0.050. Unit 2 did not change at all, because no gradient reached it.

## The same thing with matrices

Real networks do these steps for whole layers at once. For a dense layer $z = Wx + b$ with upstream gradient $\delta = \partial L / \partial z$, the three gradients are $\partial L/\partial W = \delta x^\top$, $\partial L/\partial b = \delta$ and $\partial L/\partial x = W^\top \delta$.<Cite id="cs231n-backprop" /> In the example, $\delta = [2, 0]$ and $x = [1, 2]$, so $\delta x^\top$ has rows $[2, 4]$ and $[0, 0]$: the same four weight gradients as above.

The input $x$ feeds *both* hidden units, so its gradient is the **sum** of what arrives along each path: $W^\top \delta = [0.5 \cdot 2 + 1 \cdot 0, \; 0.5 \cdot 2 + (-1) \cdot 0] = [1, 1]$. Gradients always add up where a value is used more than once.<Cite id="cs231n-backprop" /> Forgetting this, by overwriting instead of adding, is the classic bug in hand-written autograd code.<Cite id="micrograd" />

## Why it is efficient

Backpropagation reuses the values stored during the forward pass and the gradients already computed for later layers. As a result, one backward pass yields every gradient at a cost that is a small constant multiple of the forward pass, whether the network has nine parameters or a billion.<Cite id="baydin2018" /> The naive alternative, nudging each parameter separately and re-running the network, would need one extra forward pass per parameter.<Cite id="goodfellow2016-mlp" />

In computer-science terms, backpropagation is a special case of <Term slug="automatic-differentiation" /> in *reverse mode*.<Cite id="baydin2018" /> The method has a long history: Seppo Linnainmaa described reverse-mode differentiation in 1970 and Paul Werbos proposed applying it to neural networks in 1974.<Cite id="wiki-backprop" /> It became widely used after Rumelhart, Hinton and Williams showed in 1986 that it could train networks to learn useful internal representations.<Cite id="rumelhart1986" />

<Callout type="pitfall">
Backpropagation is not the learning algorithm by itself. It only computes gradients; an optimizer such as SGD or Adam decides how to use them.
</Callout>

## Checking a gradient numerically

A hand-derived gradient can be wrong, so it is worth checking it against a **numerical estimate**: nudge one parameter up and down by a small $h$ and measure the change in the loss.<Cite id="cs231n-nn3" />

CS231n recommends the centred form shown here, which is more accurate than a one-sided difference, and comparing the two values by their relative error.<Cite id="cs231n-nn3" /> Numerical checks are slow, one or two extra forward passes per parameter, so they are a debugging tool, not a training method.

## Summary

- Backpropagation computes every gradient by applying the chain rule backwards through the computational graph.
- At each node: downstream gradient = upstream gradient × local derivative. Add passes, multiply swaps, ReLU routes or blocks.
- Gradients add up where a value is used more than once.
- One backward pass costs about as much as a forward pass; it is reverse-mode automatic differentiation.
- Check hand-derived gradients with a centred difference before trusting them.
