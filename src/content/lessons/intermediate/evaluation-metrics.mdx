**Model evaluation** is the measurement of how well a trained model performs on data it has never seen. For classifiers the starting point is the **confusion matrix**, a table that counts every kind of right and wrong answer, from which accuracy, precision, recall and F1 are computed.<Cite id="sklearn-metrics" /> Choosing the right number, and measuring it on the right data, decides whether a reported score can be trusted.<Cite id="goodfellow2016-guidelines" />

## The confusion matrix

For a yes/no problem such as spam filtering, every prediction falls into one of four cells:<Cite id="mlcc-metrics" />

| | Predicted spam | Predicted not spam |
|---|---|---|
| **Really spam** | true positive (TP) | false negative (FN) |
| **Really not spam** | false positive (FP) | true negative (TN) |

A <Term slug="confusion-matrix" /> with more classes works the same way: row $i$, column $j$ counts the examples of true class $i$ predicted as class $j$. The diagonal holds the correct answers and every off-diagonal cell is a specific mistake, for example a handwritten 4 read as a 9.<Cite id="sklearn-metrics" /> Reading the off-diagonal cells is often more useful than any single score, because it shows *which* errors the model makes.

## Precision, recall and F1, with numbers

Take a spam filter tested on 100 emails, 60 of them spam. It catches 40 spam emails (TP = 40), lets 20 through (FN = 20), wrongly flags 10 good emails (FP = 10) and passes the other 30 (TN = 30).

  <Step tex="F_1 = \frac{2PR}{P + R} = \frac{2 \cdot 0.8 \cdot 0.667}{0.8 + 0.667} = \frac{1.067}{1.467} = \hl{0.727}" words="F1: the harmonic mean, which is high only when both precision and recall are high." example="plain average would give 0.733" />
</MathSteps>

<Term slug="precision-and-recall">Precision and recall</Term> answer different questions, and improving one usually costs the other. Lowering the threshold at which an email counts as spam catches more spam (recall rises) but flags more good mail (precision falls).<Cite id="wiki-pr" /> The <Term slug="f1-score" /> combines the two when a single number is needed; which of them matters more depends on what each kind of mistake costs.<Cite id="mlcc-metrics" />

<Analogy breaks="A real net has no threshold you can turn smoothly; a classifier does, which is how you trade one metric for the other.">
Think of fishing with a net. A wide, fine net catches every fish (high recall) but also boots and weeds (low precision); picking fish out by hand gets only fish (high precision) but misses many (low recall).
</Analogy>

## The accuracy trap

Accuracy is easy to explain and fine when classes are roughly balanced. On **imbalanced** data it misleads. Suppose only 10 of 1,000 emails are spam and a "model" always answers *not spam*: it scores 99.0% accuracy while catching no spam at all, a recall of 0.<Cite id="mlcc-metrics" /> Fraud, rare diseases and defects all look like this.

<Callout type="pitfall">
"99% accuracy is great." Not if 99% of the examples belong to one class. Always compare with the score of the trivial "predict the most common class" baseline, and look at per-class recall.
</Callout>

## More than two classes: macro and micro averages

With several classes, precision and recall are computed per class by treating that class as "positive" and all others as "negative". Two ways of combining them give different pictures:<Cite id="sklearn-metrics" />

- **Macro average**: compute the metric for each class, then take the plain mean. Every class counts equally, so a rare class the model ignores drags the score down.
- **Micro average**: add up the TP, FP and FN counts over all classes first, then compute the metric once. Every example counts equally; for single-label problems the micro-averaged recall equals accuracy.

In the companion script, a three-class problem with 80, 15 and 5 examples has per-class recall 0.975, 0.667 and 0.2. The micro average is 0.890 (the accuracy), while the macro average is only 0.614, which exposes the fact that the smallest class is almost never recognised.

## Which data to measure on

A score is only meaningful on data the model did not learn from. The usual practice is three disjoint splits:<Cite id="wiki-sets" /><Cite id="goodfellow2016-guidelines" />

- the **training set** fits the weights;
- the <Term slug="validation-set">validation set</Term> is used for every decision: which epoch to keep, which learning rate, which architecture;
- the **test set** is used **once**, at the end, for the number you report.

Each decision made by looking at a data set fits the model a little to that set, so a test set that influenced choices gives an optimistic score.<Cite id="d2l-generalization" /> Typical splits are 80/10/10 or 70/15/15; MNIST ships with 60,000 training and 10,000 test images, so the validation set is carved out of the training images, as in [the training loop lesson](/course/intermediate/training-loop/).

**Leakage** is the related failure where information from the evaluation data reaches training, for example the same chess position or near-duplicate photos in both splits, or normalising with statistics computed on all the data. A review of published machine-learning research found leakage behind inflated results in hundreds of papers across many fields.<Cite id="kapoor2023" /> Split first, then compute any statistics on the training split only.

## Summary

- The confusion matrix counts every kind of right and wrong answer; read its off-diagonal cells.
- Precision = TP / (TP + FP), recall = TP / (TP + FN), and F1 is their harmonic mean.
- Accuracy misleads on imbalanced data; compare with the trivial baseline and per-class recall.
- Macro averages weight classes equally, micro averages weight examples equally.
- Make decisions with the validation set and touch the test set once.
