The **Universal Chess Interface (UCI)** is the plain-text protocol through which chess GUIs, match runners and testing tools talk to engines.<Cite id="cpw-uci" /> This capstone lesson wraps the engine from the previous lessons in UCI, loads it into a graphical interface, checks that it follows the protocol, and then measures its strength against weakened Stockfish. The goal is an Elo estimate with an honest error bar, not a flattering single number.

## The UCI protocol

UCI was designed by Rudolf Huber and Stefan Meyer-Kahlen; the specification most engines follow is dated April 2006.<Cite id="uci-spec" /> The GUI writes commands to the engine's standard input and reads replies from its standard output, one line at a time. Moves are written in long algebraic notation, such as `e2e4` or `e7e8q` for a promotion.<Cite id="uci-spec" /><Cite id="cpw-uci" />

| Direction | Command | Meaning |
|---|---|---|
| GUI → engine | `uci` | identify yourself and list options, then answer `uciok` |
| GUI → engine | `isready` | answer `readyok` when ready, even during a search |
| GUI → engine | `ucinewgame`, `setoption` | reset for a new game; change an option |
| GUI → engine | `position startpos` or `position fen ...`, then `moves ...` | set up the board |
| GUI → engine | `go` with `wtime btime winc binc movestogo movetime depth nodes infinite` | start searching |
| GUI → engine | `stop`, `quit` | stop now and reply; exit |
| engine → GUI | `info depth ... score cp ... nodes ... nps ... pv ...` | progress report |
| engine → GUI | `bestmove e2e4` | the chosen move |

A short session with `uci.py` looks like this (lines from the GUI first):

```text
uci
id name AIK MiniFish 1.0
id author AI Knowledge course
option name Eval type combo default auto var auto var nn var material
...
uciok
isready
readyok
position startpos moves e2e4
go movetime 1000
info depth 1 score cp ... nodes ... nps ... time ... pv ...
bestmove ...
```

### Threading: stop, isready and bestmove

The specification requires two things that a simple loop cannot provide. `isready` must be answered even while the engine is searching, and `bestmove` must always be sent once a search ends, including after `stop`.<Cite id="uci-spec" /> `uci.py` therefore runs every search on a background thread while the main thread keeps reading commands. `stop` sets a flag that the search checks every 1,024 nodes, then waits for the thread to finish and send its move.

Three details guard the `bestmove` rule. A `go infinite` search does not reply until `stop` arrives, even if it finishes early. If the search raises an exception, the thread still sends the first legal move. If there is no legal move at all, it sends the null move `0000`. All output goes through one locked function, so `info` lines from the search never interleave with `readyok`.

### Time management and Move Overhead

Under a clock, the GUI sends the remaining time and increment for both sides. `time_budget` spends the remaining time divided by `movestogo` (30 when not given) plus 75 % of the increment, never more than half the clock, minus a safety margin called **Move Overhead**. The search then starts no new iteration after 45 % of the budget, because an unfinished deeper iteration would be wasted.

Stockfish's own Move Overhead defaults to 10 ms.<Cite id="sf-uci-commands" /> `uci.py` uses 100 ms because a Python process has slower start-up and garbage-collection pauses, and a move that arrives a few milliseconds late loses the game on time.

## Playing in a GUI

A GUI starts the engine as a program, so the project ships two tiny launchers: `minifish.bat` for Windows and `minifish.sh` for macOS and Linux. Each changes into the project folder and runs `python -u uci.py`, the `-u` keeping output unbuffered. A GUI does not activate your virtual environment, so both launchers use the course's `.venv` (in the repository folder, three levels up) when it exists and fall back to the Python on your PATH. The README explains the steps for each interface:

- [Cute Chess](https://github.com/cutechess/cutechess): add an engine with `python uci.py` (or the path to `minifish.bat`) as the command, the project folder as the working directory and UCI as the protocol.<Cite id="cutechess" />
- Arena (Windows): install a new engine and select `minifish.bat`.
- [En Croissant](https://encroissant.org/): add a local engine and pick `minifish.bat` or `minifish.sh` (run `chmod +x minifish.sh` first).

For a quick game without a GUI, `play.py` plays in the terminal; it accepts moves in standard notation such as `Nf3` or in UCI form such as `g1f3`, and prints the engine's depth, score and speed after every move.

## Checking protocol compliance

Before playing hundreds of games, check the protocol. The match runner [fastchess](https://github.com/Disservin/fastchess) has a compliance mode, run as `fastchess --compliance minifish.bat`, that sends a series of standard commands and reports any violation.<Cite id="fastchess" /> The project's own `python bench.py --uci-check` performs a similar test through python-chess, which can drive any UCI engine as a subprocess.<Cite id="python-chess-engine" />

On the course's test machine, the check read `id name AIK MiniFish 1.0` and the options Accumulator, Eval, EvalFile, Hash and Move Overhead; played 6 plies at 0.2 s per move; found the mate in one `a1a8` through `analyse`; and handled both `go infinite` followed by `stop` and a clock-based `go wtime btime winc binc`.

## Stockfish as a measuring stick

Stockfish is free and can be downloaded for every major platform.<Cite id="sf-download" /> At full strength it is hopeless as an opponent: the AlphaZero paper quotes it at about 70 million positions per second, while this Python engine searches a few thousand.<Cite id="silver2017" /> **Expect to lose every game against full-strength Stockfish.**

Stockfish offers two ways to play weaker. `Skill Level` runs from 0 to 20. `UCI_LimitStrength` with `UCI_Elo` sets a target rating between 1320 and 3190; the documentation says it is "calibrated at a time control of 120s+1s and anchored to CCRL 40/4", and that it takes precedence over Skill Level.<Cite id="sf-uci-commands" /> Only `UCI_Elo` comes with a calibration, so a Skill Level match tells you how you compare with that one opponent, not where you stand on a scale.

```bash
python bench.py --match stockfish --stockfish path/to/stockfish --sf-elo 1320 --games 50
```

fastchess runs the same kind of match through UCI, with `-repeat` playing every opening with both colours to cancel opening bias:<Cite id="fastchess" />

```text
fastchess -engine cmd=minifish.bat name=MiniFish -engine cmd=stockfish name=SF1320 option.UCI_LimitStrength=true option.UCI_Elo=1320 -each tc=60+0.6 -rounds 50 -repeat -concurrency 2
```

## Elo from a match score

An <Term slug="elo-rating">Elo rating</Term> difference predicts an expected score, and a match score can be turned back into a rating difference.<Cite id="wiki-elo" /><Cite id="cpw-match-stats" />

</MathSteps>

The lesson of the error bar is that 100 games can only separate large differences.<Cite id="cpw-match-stats" /> An estimate is most informative when the score lies between about 20 % and 80 %; near 0 % or 100 % the logarithm makes the Elo value unstable. Use two or three anchors, for example `UCI_Elo` 1320 and 1500, plus `Skill Level 0` for an engine below the 1320 floor.

`bench.py` computes all of this in `elo_report`. Its standard error uses the actual spread of results rather than the bound, so draws narrow the interval.

### SPRT: stop when the evidence is enough

To decide whether a change helps, engine developers do not fix the number of games in advance. The *Sequential Probability Ratio Test* (SPRT) plays games until the evidence clearly favours one of two hypotheses, "the gain is at most elo0" or "the gain is at least elo1", with accepted error rates alpha and beta. The Chessprogramming Wiki calls it "generally regarded as the most important process in modern engine development" and gives the fastchess form `-sprt elo0=0 elo1=5 alpha=0.05 beta=0.05`.<Cite id="cpw-sprt" /> Stockfish's distributed testing (Fishtest) uses even tighter bounds, such as elo0=0 and elo1=2.<Cite id="cpw-sprt" />

A learner engine makes big jumps, such as adding quiescence or the network, so wider bounds like `elo0=0 elo1=20` or `elo1=50` are a sensible choice that finishes in tens to a few hundred games. This is a recommendation, not a rule.

<Analogy breaks="A coin has one fixed bias; an engine's result also depends on the openings, the time control and the opponent.">
SPRT is like testing whether a coin is fair by flipping it only until you are confident, instead of committing to 10,000 flips up front.
</Analogy>

## Honest expectations

The project's research gives strength ranges for each stage, and they are estimates, not measurements: about 1300 to 1600 for the piece-square engine with ordering, quiescence, iterative deepening and a transposition table, and a further +50 to +250 Elo for the trained network. Treat them as a guess to beat or disprove.

The course's test runs played short matches against Stockfish 19 with `UCI_LimitStrength` and `UCI_Elo 1320`, at 0.3 s per move for both sides:

| Engine | Games | Wins / draws / losses | Elo difference (95 % interval) | Rough rating on Stockfish's scale |
|---|---|---|---|---|
| Piece-square tables | 10 | 7 / 2 / 1 | +241 (+66 to no upper bound) | about 1560 |
| Network, 1 M Lichess positions | 10 | 4 / 2 / 4 | 0 (−217 to +217) | about 1320 |

Read these with care. Ten games give intervals hundreds of points wide, and Stockfish calibrates `UCI_Elo` at 120 s + 1 s per game, not at 0.3 s per move.<Cite id="sf-uci-commands" /> The results agree in direction with the direct match in the previous lesson, where the network lost to the tables. The piece-square result falls inside the research's 1300 to 1600 estimate; the network's does not yet show the hoped-for gain. Against Skill Level 0, the piece-square engine won 2 of 2 test games, and a 100 % score has no finite Elo estimate.

Any number you produce lives on Stockfish's CCRL-anchored engine scale. It is not a FIDE or Lichess rating; Stockfish's FAQ notes that comparing engine ratings with FIDE Elo "has become virtually impossible".<Cite id="sf-faq" /> To measure your own numbers, report the anchor, the time control, the number of games, the W/D/L counts and the 95 % interval, and say what machine you used. Never quote the single Elo value alone.

## Summary

- UCI is a line-based text protocol; the engine must answer `isready` at any time and always finish a search with `bestmove`, which is why the search runs on its own thread.
- The time budget is a fraction of the clock plus most of the increment, capped at half the clock, minus a Move Overhead margin (100 ms here, 10 ms by default in Stockfish).
- Elo difference is 400·log₁₀(s/(1−s)); at 100 games the 95 % interval is about ±70 Elo, and SPRT decides A/B tests with as few games as the evidence allows.
- `UCI_Elo` (1320 to 3190) is calibrated to CCRL 40/4, so results are engine-scale estimates, not FIDE or Lichess ratings; full-strength Stockfish wins every game.
- python-chess and Stockfish are GPL-3; the course code is MIT and only imports python-chess.
