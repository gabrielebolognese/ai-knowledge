A **static evaluation** looks at one frozen position, without searching any further, and returns a single number that says who is better and by how much.<Cite id="cpw-pst" /> The number is measured in <Term slug="centipawn">centipawns</Term>, where 100 means roughly one pawn's advantage.<Cite id="cpw-simplified-eval" /> This lesson builds the classic baseline evaluator, piece values plus piece-square tables, and makes it the single function `evaluate(board)` that the search calls and that a trained network will later replace.

## Material

The simplest useful evaluation counts material. The companion code uses the values from Tomasz Michniewski's **Simplified Evaluation Function**, a deliberately small evaluator published on the Chessprogramming Wiki:<Cite id="cpw-simplified-eval" />

| Piece | Pawn | Knight | Bishop | Rook | Queen | King |
|---|---|---|---|---|---|---|
| Value (cp) | 100 | 320 | 330 | 500 | 900 | 20,000 |

The bishop is given a small edge over the knight, and the king's huge value simply means "cannot be traded".<Cite id="cpw-simplified-eval" /> The companion code sets the king to 0 instead: both sides always have exactly one, so it cancels out, and checkmate is detected by the search, not by the evaluation. Material is White's total minus Black's total, so the start position scores 0.

python-chess makes the counting cheap: `board.pieces_mask(piece_type, color)` returns a bitboard of those pieces, and `chess.popcount` counts its set bits.<Cite id="python-chess-core" />

## Piece-square tables

Material alone cannot tell a knight in the centre from a knight stuck in a corner. A **piece-square table** (PST) adds a small bonus or penalty for every piece type on every square.<Cite id="cpw-pst" /> In Michniewski's tables a knight in a corner gets −50 and one in the centre +20; a pawn that reaches the seventh rank gets +50; the untouched centre pawns on d2 and e2 get −20, which nudges the engine to develop them; and in the middlegame the king prefers a castled square such as g1 (+30) to the centre.<Cite id="cpw-simplified-eval" />

<Analogy breaks="A house keeps its value whoever lives next door, but a chess piece's real worth depends on the other pieces around it, which a table cannot see.">
Material is counting the money in each player's wallet. Piece-square tables are "location, location, location": the same house is worth more in a good neighbourhood.
</Analogy>

The tables are written the way a chess diagram is printed, rank 8 at the top. python-chess numbers squares from `a1 = 0` to `h8 = 63`, rank 1 first, so the code needs one small index conversion:<Cite id="python-chess-core" />

For a White piece, `square ^ 56` flips the rank (a1 becomes index 56, the bottom-left of the printed table). A Black piece looks at the board from the other side, so its own square number already points to the right entry: a Black pawn on rank 2 picks up the same +50 that a White pawn gets on rank 7.

The king needs different advice in the endgame, where it should walk to the centre instead of hiding. Michniewski's rule switches to an endgame king table when neither side has a queen, or when every side with a queen has at most one minor piece and no rook.<Cite id="cpw-simplified-eval" /> Most modern engines go further: they keep a full opening set and a full endgame set of tables and blend the two smoothly according to how much material is left, a technique called a **tapered evaluation**.<Cite id="cpw-pst" /><Cite id="cpw-tapered" />

## Why the score is relative to the side to move

The search in the next lesson is written as **negamax**: one function serves both players by flipping the sign of the score at every move. That trick only works if the evaluation always answers "how good is this for the player to move?".<Cite id="cpw-negamax" /> The companion code therefore computes the White-relative score once and negates it when Black is to move. A score of +50 always means "the player whose turn it is stands half a pawn better".

<Callout type="pitfall">
Sign bugs are the most common error in a first engine. A White-relative evaluation plugged into negamax makes Black play the moves that are best for White, and the engine looks as if it were giving pieces away on purpose. Test the sign with `board.mirror()`, which flips the board, swaps the colours and the side to move: the score must stay exactly the same.<Cite id="python-chess-core" />
</Callout>

## A piece-square table is a linear model

Describe a position by 768 yes/no inputs, one for every combination of colour (2), piece type (6) and square (64): an input is 1 if that piece stands on that square and 0 otherwise, so at most 32 of them are 1. Give each input a number, its <Term slug="weight" />, equal to the piece value plus its table entry, with a minus sign for Black pieces. The material + PST score is then exactly the <Term slug="dot-product" /> of the inputs with the weights, $E_{white} = \sum_i w_i x_i$: a **linear model** with 768 weights, the same form as a single <Term slug="artificial-neuron" /> without an activation function.

This view explains both the strength and the limit of the tables. Each weight answers one question about one piece on one square, so a linear model cannot express a *combination* such as "the two bishops together are worth a bonus" or "a weak king matters more while the queens are on". The neural evaluator later in this track keeps exactly the same 768 inputs, which is also the simplest feature set described in Stockfish's NNUE documentation, and adds hidden layers so it can learn such combinations from data.<Cite id="nnue-doc" /> In the companion code Black reuses White's tables mirrored, so only 384 of the 768 numbers are independent; a [trained network](/course/project-chess/chess-train-evaluator/) learns all of its weights from data instead.

## Summary

- A static evaluation scores one position in centipawns; 100 cp is about one pawn.
- Material uses fixed piece values (here 100, 320, 330, 500, 900); piece-square tables add a bonus or penalty per piece per square.
- Negamax needs the score from the side to move's point of view: negate the White-relative score when Black is to move, and test it with a mirrored position.
- Material + PST is a linear model with 768 weights; the neural evaluator keeps the same inputs and adds hidden layers to learn combinations.
