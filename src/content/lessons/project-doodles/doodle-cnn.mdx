A **doodle classifier** is a neural network that takes a small sketch and says which object it shows. This lesson trains one with the same <Term slug="convolutional-neural-network">convolutional network</Term> used for handwritten digits, changing only the data: 90,000 Quick, Draw! drawings of ten everyday objects.<Cite id="quickdraw-repo" /> On a laptop CPU it reaches about 95.7% test accuracy in roughly four minutes, against about 99% for digits, and the curves show what happens in each epoch.

## The same network, new data

The doodle bitmaps have exactly the format of MNIST: 28×28 pixels, one channel, white strokes on black. So the model needs no change except the number of outputs, which is ten here as well. `DoodleCNN` is the digits CNN with one optional extra, batch normalization, which stays off until the next lesson.

<CodeFile path="code/projects/project-doodles/models.py" lines="11-39" highlight="23,28,29,32,34" title="models.py: DoodleCNN" />

Two convolutional blocks turn the 28×28 image into 64 feature maps of 7×7; each block is a 3×3 convolution, a ReLU and a 2×2 max-pool.<Cite id="pt-conv2d" /> A fully connected layer of 128 units with <Term slug="dropout" /> then produces ten scores, one per class. `python models.py` confirms 421,642 parameters, the same count as for digits.

<Analogy breaks="A person who has learned to read digits does not need retraining to look at sketches; the network keeps only its architecture and starts again from random weights.">
Using the same network on doodles is like giving the same pair of eyes a new picture book: the machinery for finding edges, corners and loops is the same, but what those parts add up to has to be learned again.
</Analogy>

Why does a network built for digits suit sketches at all? Convolutional layers assume that useful patterns are local and can appear anywhere in the image, and that holds for strokes of any kind.<Cite id="cs231n-cnn" /> Early filters learn short line segments and curves; later ones combine them into parts such as a roof corner, a whisker or a clock hand.

## The training loop, with a validation check

`train.py` follows the standard five steps per batch: forward pass, loss, clear the old gradients, backpropagation, update. The loss is <Term slug="cross-entropy" />, which applies softmax to the ten raw scores and penalises a low probability for the correct class.<Cite id="pt-ce" /> The optimiser is Adam with a learning rate of 0.001, a common default that adapts the step size of each weight separately.<Cite id="kingma2014" />

<CodeFile path="code/projects/project-doodles/train.py" lines="47-69" highlight="48,51,52,53,54,55,64" title="train.py: one epoch, and accuracy on a held-out set" />

After every epoch the script measures accuracy on the 10,000 validation doodles, which the model never trains on. The test set is used only once, at the very end. This keeps the test result honest: any setting you choose by looking at validation curves (number of epochs, dropout, augmentation) has not been tuned on the test data.

## Results on a CPU

Measured on the course's test machine (Windows 11 laptop CPU, PyTorch 2.15 CPU build, default seed), `python train.py` took 4 minutes 16 seconds for five epochs:

| Epoch | Train loss | Train accuracy | Validation accuracy | Time so far |
|---|---|---|---|---|
| 1 | 0.484 | 85.34% | 92.72% | 49 s |
| 2 | 0.264 | 92.33% | 94.01% | 96 s |
| 3 | 0.222 | 93.55% | 95.17% | 145 s |
| 4 | 0.193 | 94.30% | 95.28% | 196 s |
| 5 | 0.171 | 94.95% | **95.75%** | 242 s |

The final test accuracy was **95.67%** on 20,000 doodles: 865 mistakes. The planning estimate for this project was 88-93%; these ten classes turned out easier than expected because they look quite different from one another. Expect a few tenths of a percent of variation between machines and seeds, and lower numbers if you pick classes that resemble each other.

### Reading the curves

Validation accuracy is *above* training accuracy in every epoch. That looks wrong but is normal here, for two reasons. First, the training figure is averaged over the epoch while the model is still improving, so early batches drag it down. Second, it is measured with dropout active, which removes half of the hidden units at every step; validation is measured in evaluation mode with all units present.<Cite id="d2l-dropout" />

The warning sign to watch for is the opposite: training accuracy climbing while validation accuracy stalls or falls. That gap is overfitting, and the next lesson measures how much dropout and other regularisers prevent it.

## Why doodles are harder than digits

On MNIST the same network reaches about 99% in three epochs; here it reaches 95.7% in five. The data explains most of the gap:

- **More variety per class.** A digit has a handful of standard shapes. A cat can be a face with whiskers, a whole body from the side, or a few loops.
- **Rough, unfinished drawings.** Players had at most 20 seconds per word, so many sketches are minimal or incomplete.<Cite id="ha2017" />
- **Loose labels.** The data keeps every moderated drawing with the word the player was given, including drawings the game failed to recognise, and each record notes whether it was recognised.<Cite id="quickdraw-repo" /> A "cloud" that is a single line is labelled cloud all the same.

The sketch-rnn authors also observed that their generative model struggled once it had to cover many classes at once: samples from a model trained on 75 classes mixed features of several objects.<Cite id="ha2017" /> Classification with a small CNN shows a milder version of the same effect: every class you add brings new look-alikes.

## Try it

From `code/projects/project-doodles/`, after `python download.py`:

```bash
python train.py --smoke     # 2 classes x 500 doodles, 2 epochs: about 2 s of training
python train.py             # 10 classes, 5 epochs: about 4 minutes on a laptop CPU
python train.py --epochs 8  # a longer run; compare the validation curve
```

The smoke test is a setup check, not a result. It needs `python download.py --smoke` first and confirms that the loss falls below $\ln 2 \approx 0.69$ (95.8% test accuracy on 166 doodles on the test machine). Each run saves a checkpoint in `checkpoints/`, the history as JSON in `outputs/`, and the curves as a PNG.

## Summary

- The doodle bitmaps have MNIST's format, so the digits CNN (421,642 parameters) works without changes.
- Five epochs on 90,000 doodles took about four minutes on a CPU and reached 95.67% test accuracy, against about 99% for digits.
- The first loss should be near $\ln 10 \approx 2.30$; a validation set checked after each epoch guides decisions, and the test set is used once.
- Validation above training is expected early on (running average, dropout on); training clearly above validation would mean overfitting.
- Doodles are harder because of variety within classes, rough unfinished drawings and loose labels.
