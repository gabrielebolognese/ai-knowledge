Most setup problems come from a handful of causes: a terminal that was opened **before** an install, the wrong Python answering, or an environment that is not active. This lesson lists the common error messages with their fixes, then covers the optional extras: **Git**, **GitHub Desktop** and **WSL2**.<Cite id="py-using-windows" />

<Callout type="tip">
Before anything else: **close the terminal, open a new one**, activate `.venv`, and try again. A terminal reads the <Term slug="path-variable">PATH</Term> only when it starts.
</Callout>

## First, diagnose

These three commands tell you which Python is answering and whether the environment is active:

```text
python --version
python -c "import sys; print(sys.executable)"
python -m pip --version
```

Inside an active environment, the second and third lines show a path containing **`.venv`**. On Windows, `py list` shows every runtime the install manager knows about, with the default marked.<Cite id="py-using-windows" />

## Windows

### `python` opens the Microsoft Store, or says "Python was not found"

Windows ships a shortcut, an *app execution alias*, that answers `python` with the Store when no real Python is found.<Cite id="py-using-windows" />

1. **Start** → type **Manage app execution aliases** → open it.
2. **Install manager users:** make sure **Python (default)** and **Python install manager** are **On**; toggle them off and on to refresh.
3. **Classic installer users:** switch **off** the aliases that point to the Store's *App Installer*.
4. Open a **new** terminal.

See the illustration in [Install Python](/course/setup/setup-install-python/).

### `python` or `py` is "not recognized"

- Open a new terminal (see the tip above).
- **Install manager:** check that `py` and `pymanager` work; confirm that `%UserProfile%\AppData\Local\Microsoft\WindowsApps` is on PATH.<Cite id="py-using-windows" />
- **Classic installer:** re-run the installer, choose **Modify → Next**, tick **Add Python to environment variables**, then **Install**.
- **Edit PATH by hand:** **Start** → **Edit environment variables for your account** → select **Path** → **Edit** → **New**, add the folder, click **OK**, open a new terminal.

### `py` says "can't open file", or `python` and `py` run different versions

An older *Python launcher* from a classic install is taking priority. Remove it in **Settings → Apps → Installed apps** (entry **Python Launcher**), and uninstall Python versions you no longer use.<Cite id="py-using-windows" />

### "Running scripts is disabled on this system"

PowerShell blocks `Activate.ps1` by default. Run this once, then activate again:<Cite id="ps-execution-policy" />

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

No-change alternatives: use **Command Prompt** with `.venv\Scripts\activate.bat`, or call `.venv\Scripts\python.exe` directly.

### "Path too long", `WinError 206` or install failures in deep folders

Windows has a historic 260-character path limit. Keep the course in a short folder such as `C:\dev\ai-knowledge`. To lift the limit (administrator, then restart), set the registry value `LongPathsEnabled` to `1` under `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`, or click **Disable path length limit** at the end of the classic installer.<Cite id="py-using-windows" />

### Very slow or broken `.venv` inside OneDrive

Sync services struggle with the thousands of small files in an environment. Move the project to `C:\dev\ai-knowledge`, delete the old `.venv` folder and create it again (lesson 5).

## All systems

### "pip is not recognized" / "command not found: pip"

Use **`python -m pip`** (macOS/Linux outside a venv: `python3 -m pip`). It runs pip through the Python that already works.<Cite id="pip-user-guide" /> If pip is missing entirely, `python -m ensurepip --upgrade` restores it.<Cite id="pip-install" />

### "ERROR: No matching distribution found for torch"

Almost always the Python version or architecture. PyTorch 2.15 needs **64-bit Python 3.11 or newer**.<Cite id="pypi-torch" /> Check with:

```text
python --version
python -c "import struct; print(struct.calcsize('P') * 8)"
```

The second line must print `64`. On an **Intel Mac** there is no current PyTorch build: use [Google Colab](/course/setup/setup-colab/). On exactly Python **3.14.1**, torchvision refuses to install: upgrade to the latest 3.14.

### `torch.cuda.is_available()` is `False`

Expected with the CPU build (version ends in `+cpu`). With a CUDA build, run `nvidia-smi`: the driver must be 580 or newer for CUDA 13. See [Install PyTorch](/course/setup/setup-install-pytorch/).

### "SSL: CERTIFICATE_VERIFY_FAILED" or pip cannot connect

- **macOS:** double-click **Install Certificates.command** in `/Applications/Python 3.14/`.<Cite id="py-using-mac" />
- **School or work network:** a proxy may be in the way. pip accepts `--proxy http://host:port`.<Cite id="pip-user-guide" /> If the network inspects HTTPS, ask IT for its certificate file and pass it with `--cert`. Do not make `--trusted-host` a habit, since it skips security checks. The easy way out is [Colab](/course/setup/setup-colab/).

### "externally-managed-environment" (Linux, Homebrew)

The system Python refuses pip installs by design (PEP 668).<Cite id="pep-668" /> Activate your `.venv`. On Debian/Ubuntu, *"ensurepip is not available"* means `sudo apt install python3-venv` is missing.

### A package is installed but its command is "not found" (e.g. `jupyter`)

Activate the environment, or run it as a module: `python -m jupyter lab`.

### VS Code underlines `import torch` in red, or a notebook asks for a kernel

VS Code is using another Python. **Ctrl+Shift+P → Python: Select Interpreter → `.venv`**. In a notebook, click **Select Kernel → Python Environments… → `.venv`**, and accept if VS Code offers to install `ipykernel`.<Cite id="vscode-python-envs" />

### `UnicodeDecodeError` when reading a text file on Windows

Open files with `open(path, encoding="utf-8")`. Python 3.15 makes UTF-8 the default, but 3.14 on Windows does not.<Cite id="py-using-windows" />

## Optional: Git and GitHub Desktop

The course is read-only, and **Download ZIP** from GitHub is enough to get the code. Git is useful if you want to pull updates or track your own changes.

### Git for Windows

Open [git-scm.com/install/windows](https://git-scm.com/install/windows) and click **Click here to download** (the latest 64-bit installer). Run it and accept the defaults.<Cite id="git-windows" />

<Screenshot src="/screenshots/setup/git-for-windows-download.png" alt="git-scm.com Install for Windows page with the 'Click here to download' link outlined" caption="git-scm.com/install/windows. The page also lists ARM64, portable and winget options." source="https://git-scm.com/install/windows" taken="2026-11-25" pins={[{ label: 'Click **Click here to download** for the latest x64 Git for Windows.' }]} />

**Verify it worked:** in a new terminal, `git --version` prints `git version 2.56.1.windows.1` or newer. Then get the course code:

```text
cd C:\dev
git clone https://github.com/gabrielebolognese/ai-knowledge.git
```

On macOS, typing `git --version` in Terminal offers to install Apple's command-line tools, which include Git. On Linux, `sudo apt install git` or `sudo dnf install git`.

### GitHub Desktop

Prefer buttons to commands? Open [desktop.github.com/download](https://desktop.github.com/download/) and click **Download for Windows** (or macOS).<Cite id="github-desktop" /> Sign in with a GitHub account, then use **File → Clone repository → URL** and paste `https://github.com/gabrielebolognese/ai-knowledge`.<Cite id="gh-desktop-docs" />

## Optional: WSL2 (advanced)

The **Windows Subsystem for Linux** runs a real Linux, such as Ubuntu, inside Windows; install it with `wsl --install` in an administrator terminal.<Cite id="wsl-install" /> It helps if you already prefer Linux tools or follow Linux-only guides. It is **not needed** for this course: every lesson works in normal Windows PowerShell, and WSL adds a second set of files and Pythons to keep track of.

## Summary

- First fix: **new terminal**, activate `.venv`, retry. Diagnose with `sys.executable` and `python -m pip --version`.
- Store opens → **Manage app execution aliases**. Scripts disabled → `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser`.
- pip missing → `python -m pip`. No torch for your Python → 64-bit Python 3.11+ (not 3.14.1), or Colab.
- Git ([git-scm.com/install/windows](https://git-scm.com/install/windows)), GitHub Desktop and WSL2 are optional.
